interface / default / inheritance

Q296. 出力は？

interface Label {
    default String text() { return "I"; }
}
class Parent {
    public String text() { return "C"; }
}
class Child extends Parent implements Label { }

System.out.println(new Child().text());
A. I
B. C
C. コンパイルエラー
答え・解説
B。C。クラスから継承したインスタンスメソッドは、interfaceのdefaultメソッドより優先されます。ChildはParent.text()をそのまま利用します。
interface / modifiers / compile error

Q297. 次のコードはコンパイルできる？

interface Rate {
    int STEP = 2;
}
class Use {
    void bump() {
        Rate.STEP++;
    }
}
A. できる
B. できない
答え・解説
B。interfaceのフィールドには暗黙でpublic static finalが付きます。STEPは定数なので、++で値を書き換えることはできません。
interface / abstract / access modifier / compile error

Q298. Fullはコンパイルできる？

interface Work {
    void open();
    void close();
}
abstract class Half implements Work {
    public void open() { }
}
class Full extends Half {
    void close() { }
}
A. できる
B. できない
答え・解説
B。Halfはabstractなのでclose()を未実装のままにできますが、具象クラスFullは実装が必要です。interface由来のclose()はpublicなので、Full側もpublicで実装しなければなりません。
constructor / super / argument evaluation / trace

Q299. 出力は？

class Parent {
    Parent(int n) { System.out.print("P" + n); }
}
class Child extends Parent {
    static int make() {
        System.out.print("M");
        return 4;
    }
    Child() {
        super(make());
        System.out.print("C");
    }
}

new Child();
A. P4MC
B. MP4C
C. MPC4
答え・解説
B。MP4C。super(...)へ渡す引数は親コンストラクタを呼ぶ前に評価されるため、まずmake()のM、その後ParentのP4、最後にChildのCが出力されます。
static / initialization order / trace

Q300. 出力は？

class Config {
    static int a = readB();
    static int b = 7;

    static int readB() {
        return b + 1;
    }
}

System.out.println(Config.a + ":" + Config.b);
A. 1:7
B. 8:7
C. 8:8
答え・解説
A。1:7。staticフィールドは宣言順に初期化されます。aを求める時点ではbはまだ明示初期化前で既定値0なので、readB()は1を返します。その後bが7になります。
constructor / super / compile error

Q301. 次のChildはコンパイルできる？

class Parent {
    Parent(int n) { }
}
class Child extends Parent {
    Child() {
        int n = 3;
        super(n);
    }
}
A. できる
B. できない
答え・解説
B。コンストラクタで明示的にsuper(...)やthis(...)を呼ぶ場合、その呼び出しは先頭文でなければなりません。ローカル変数宣言を先に置くことはできません。
Map / null / containsKey

Q302. 出力は？

Map<String,Integer> map = new HashMap<>();
map.put("x", null);

System.out.println(
    (map.get("x") == null) + ":" +
    map.containsKey("x") + ":" +
    map.containsKey("y")
);
A. true:true:false
B. true:false:false
C. false:true:false
答え・解説
A。HashMapではnull値を保持できます。get()がnullでも「キーがない」とは限らず、containsKey()を使えばxが登録済みであることを区別できます。
Map / put / return value

Q303. 出力は？

Map<String,Integer> map = new HashMap<>();
Integer a = map.put("k", 1);
Integer b = map.put("k", 5);

System.out.println(a + ":" + b + ":" + map.get("k"));
A. null:1:5
B. 1:5:5
C. null:5:1
答え・解説
A。put()はそのキーに以前対応していた値を返します。初回は以前の値がないためnull、2回目は旧値1が返り、最終的な値は5です。
TreeSet / order / mutation

Q304. 出力は？

TreeSet<Integer> set = new TreeSet<>();
set.add(3);
set.add(1);
set.add(2);

Integer first = set.pollFirst();
System.out.println(first + ":" + set);
A. 1:[2, 3]
B. 3:[1, 2]
C. 1:[1, 2, 3]
答え・解説
A。TreeSetは自然順序で保持され、pollFirst()は最小要素を取得すると同時に削除します。1が取り除かれ、残りは[2, 3]です。
LinkedHashMap / overwrite / order

Q305. 出力は？

Map<String,Integer> map = new LinkedHashMap<>();
map.put("b", 1);
map.put("a", 2);
map.put("b", 9);

System.out.println(map.keySet());
A. [a, b]
B. [b, a]
C. [b, a, b]
答え・解説
B。[b, a]。同じキーbへのputは値を上書きするだけで、新しいキーを追加しません。通常のLinkedHashMapは最初に挿入されたキー順を保つため、bの位置も変わりません。
array / enhanced for / reference

Q306. 出力は？

StringBuilder[] a = {
    new StringBuilder("A"),
    new StringBuilder("B")
};

for (StringBuilder s : a) {
    s.append("!");
    s = new StringBuilder("X");
}

System.out.println(a[0] + ":" + a[1]);
A. A:B
B. A!:B!
C. X:X
答え・解説
B。append()は配列要素が参照しているStringBuilder自体を変更するため反映されます。一方、拡張forの変数sへ別オブジェクトを代入しても、配列中の参照は置き換わりません。
while / post-increment / trace

Q307. 出力は？

int i = 0;
int sum = 0;

while (i++ < 3) {
    sum += i;
}

System.out.println(i + ":" + sum);
A. 3:6
B. 4:6
C. 4:10
答え・解説
B。4:6。条件判定では比較に増加前の値を使い、その直後にiが増えます。ループ本体では1、2、3を加え、最後の条件判定でもi++が実行されて4になります。
nested loop / break / trace

Q308. 出力は？

int count = 0;
for (int i = 0; i < 3; i++) {
    for (int j = 0; j < 3; j++) {
        if (i == j) break;
        count++;
    }
}
System.out.println(count);
A. 3
B. 6
C. 9
答え・解説
A。breakが終了させるのは内側のforだけです。i=0では0回、i=1では1回、i=2では2回count++され、合計3になります。
array / instanceof / cast model

Q309. 出力は？

Object x = new int[2];

System.out.println(
    (x instanceof Object) + ":" +
    (x instanceof int[]) + ":" +
    (x instanceof Object[])
);
A. true:true:false
B. true:true:true
C. false:true:false
答え・解説
A。配列はObjectですが、int[]はプリミティブ型要素の配列なのでObject[]ではありません。したがってObjectとint[]の判定はtrue、Object[]はfalseです。
instanceof / cast / null

Q310. 出力は？

class Parent { }
class Child extends Parent { }

Parent p = null;
Child c = (Child) p;

System.out.println((p instanceof Parent) + ":" + (c == null));
A. false:true
B. true:true
C. ClassCastException
答え・解説
A。nullに対するinstanceofはfalseです。また、null参照を互換性のある参照型へキャストしても例外にはならず、結果はnullのままです。
instanceof / compile error / type relation

Q311. 次のコードはコンパイルできる？

String s = "java";
System.out.println(s instanceof Integer);
A. できてfalseを表示する
B. できない
答え・解説
B。StringとIntegerは継承関係のないfinalクラスで、String参照がIntegerオブジェクトを指す可能性はありません。このinstanceofは型として成立せずコンパイルエラーです。
boolean / short-circuit / side effect

Q312. 出力は？

int n = 0;
boolean a = true || (++n > 0);
boolean b = false || (++n > 0);

System.out.println(n + ":" + a + ":" + b);
A. 0:true:true
B. 1:true:true
C. 2:true:true
答え・解説
B。最初の||は左辺がtrueなので右辺を評価せずnは増えません。2つ目は左辺がfalseなので右辺を評価し、nが1になって条件もtrueになります。
Thread / Runnable / run / start / join

Q313. 出力は？

class Task implements Runnable {
    int n = 0;
    public void run() { n++; }
}

Task task = new Task();
Thread t = new Thread(task);

task.run();
t.start();
t.join();

System.out.println(task.n);
A. 1
B. 2
C. 必ずしも決まらない
答え・解説
B。task.run()は通常のメソッド呼び出しとして1回実行されます。その後t.start()で同じTaskのrun()が別スレッドからもう1回実行され、join()で終了を待つため最終値は2です。
Thread / join / lifecycle

Q314. 出力は？

Thread t = new Thread(() -> System.out.print("B"));

t.join();
System.out.print("A");
A. A
B. BA
C. コンパイルエラー
答え・解説
A。start()していないThreadは生存していないため、join()は待たずに戻ります。run()は一度も開始されないのでBは出力されず、Aだけが表示されます。例外処理またはthrows宣言は済んでいるものとします。
Thread / sleep / static

Q315. 出力として正しいものは？

Thread worker = new Thread(() -> System.out.print("W"));

System.out.print("A");
worker.sleep(10);
System.out.print("B");
A. AB
B. AWB
C. コンパイルエラー
答え・解説
A。Thread.sleep(...)はstaticメソッドなので、worker経由で呼ぶ書き方でも休止するのは呼び出し元の現在スレッドです。workerはstart()されていないためWは出力されません。例外処理またはthrows宣言は済んでいるものとします。

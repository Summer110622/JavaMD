interface / static / compile error

Q196. 次のAppはコンパイルできる？

interface Tools {
    static int code() { return 7; }
}
class App implements Tools {
    int read() { return code(); }
}
A. でき、read()は7を返す
B. でき、read()は0を返す
C. できない
答え・解説
C。 interfaceのstaticメソッドは実装クラスへ継承されません。Tools.code()のようにinterface名で呼び出す必要があります。
inheritance / private / @Override

Q197. 次のChildはコンパイルできる？

class Base {
    private void ping() { }
}
class Child extends Base {
    @Override
    public void ping() { }
}
A. できる
B. できない
答え・解説
B。 BaseのprivateメソッドはChildへ継承されず、オーバーライド対象になりません。そのため@Overrideを付けるとコンパイルエラーです。
interface / access modifier

Q198. 次のBaseJobはコンパイルできる？

interface Job {
    void work();
}
abstract class BaseJob implements Job {
    protected void work() { }
}
A. abstract classなのでできる
B. protectedでも実装できる
C. できない
答え・解説
C。 interfaceの抽象メソッドは暗黙にpublicです。同じシグネチャを実装するメソッドのアクセス範囲をprotectedへ狭めることはできません。
constructor / override / initialization

Q199. 出力は？

class Parent {
    Parent() { System.out.print(value()); }
    int value() { return 1; }
}
class Child extends Parent {
    int n = 5;
    int value() { return n; }
}
new Child();
A. 0
B. 1
C. 5
答え・解説
A。0。 Parentのコンストラクタ中でもオーバーライドされたChild.value()が呼ばれます。その時点ではChild側のフィールド初期化n = 5より前なので、nは既定値0です。
this / super / constructor chain

Q200. 出力は？

class Parent {
    Parent(int n) { System.out.print("P" + n); }
}
class Child extends Parent {
    Child() { this(2); System.out.print("A"); }
    Child(int n) { super(n + 1); System.out.print("B"); }
}
new Child();
A. P3BA
B. P2AB
C. AP3B
答え・解説
A。P3BA。 Child()は最初にthis(2)を呼び、そのコンストラクタがsuper(3)を実行します。Parent → Child(int) → Child()の残り、の順です。
static / null reference

Q201. 次のコードはどうなる？

class Counter {
    static int total = 4;
}
Counter c = null;
System.out.println(c.total);
A. 4と表示
B. NullPointerException
C. コンパイルエラー
答え・解説
A。4。 staticフィールドはインスタンスではなくクラスに属します。この書き方は推奨されませんが、参照cを実体として参照せずCounterのstaticメンバとして解決されるため例外にはなりません。
Map / putAll

Q202. 出力は？

Map<String,Integer> a = new HashMap<>();
a.put("A", 1);
a.put("B", 2);
Map<String,Integer> b = new HashMap<>();
b.put("B", 9);
b.put("C", 3);
a.putAll(b);
System.out.println(a.get("B") + ":" + a.size());
A. 2:4
B. 9:3
C. 9:4
答え・解説
B。9:3。 putAllでは同じkey Bのvalueが9へ上書きされ、Cが追加されます。keyはA・B・Cの3個です。
TreeMap / key order

Q203. 出力は？

TreeMap<Integer,String> m = new TreeMap<>();
m.put(30, "C");
m.put(10, "A");
m.put(20, "B");
System.out.println(m.firstKey() + ":" + m.lastKey());
A. 30:20
B. 10:30
C. 30:10
答え・解説
B。10:30。 TreeMapはkeyを自然順序で管理します。firstKey()は最小key、lastKey()は最大keyを返します。

List<String> xs =

Iterator / remove

Q205. 出力は？

List<Integer> xs =
    new ArrayList<>(Arrays.asList(1, 2, 3));
Iterator<Integer> it = xs.iterator();
while (it.hasNext()) {
    int v = it.next();
    if (v % 2 == 1) {
        it.remove();
    }
}
System.out.println(xs);
A. [1, 2, 3]
B. [2]
C. ConcurrentModificationException
答え・解説
B。[2]。 Iteratorで走査中に、直前のnext()で得た要素をIterator.remove()で削除するのは正しい操作です。奇数1と3が削除されます。
array / Arrays.copyOf

Q206. 出力は？

int[] a = {4, 5};
int[] b = Arrays.copyOf(a, 4);
System.out.println(b[2] + ":" + b.length);
A. 0:4
B. 5:4
C. ArrayIndexOutOfBoundsException
答え・解説
A。0:4。 長い配列へコピーすると、元に存在しない追加部分は要素型の既定値で初期化されます。intの既定値は0です。
array / reference parameter

Q207. 出力は？

static void change(int[] x) {
    x[0] = 7;
    x = new int[] {9};
    x[0] = 8;
}

int[] a = {1};
change(a);
System.out.println(a[0]);
A. 1
B. 7
C. 8
答え・解説
B。7。 配列参照も値渡しです。最初のx[0] = 7は元配列を変更しますが、その後xへ新しい配列を代入しても呼び出し側の変数aは付け替わりません。
for / continue / update

Q208. 出力は？

int i = 0;
int sum = 0;
for (; i < 4; sum += i, i++) {
    if (i == 1) {
        i++;
        continue;
    }
}
System.out.println(i + ":" + sum);
A. 4:3
B. 4:5
C. 3:5
答え・解説
B。4:5。 continueでもfor文の更新式は実行されます。i=1の反復では本体でiが2になり、その後更新式でsumに2を加えてiを3へ進めます。
instanceof / sibling class

Q209. 出力は？

class Animal { }
class Cat extends Animal { }
class Dog extends Animal { }

Animal a = new Cat();
System.out.println(a instanceof Dog);
A. true
B. false
C. コンパイルエラー
答え・解説
B。false。 変数aの宣言型AnimalはDogを参照できる型なので式自体はコンパイル可能です。ただし実体はCatなのでinstanceof Dogはfalseです。

Q210. 出力は？

Object o = null;

boolean / non-short-circuit

Q211. 出力は？

int n = 0;
boolean b = false & (++n > 0);
System.out.println(n + ":" + b);
A. 0:false
B. 1:false
C. 1:true
答え・解説
B。1:false。 booleanに対する&は両辺を評価します。左辺がfalseでも++nが実行されます。結果全体はfalseです。

Thread / isAlive / join

Q213. 最後の出力は？

Thread t = new Thread(() -> { });
t.start();
t.join();
System.out.println(t.isAlive());
A. true
B. false
C. 必ずしも決まらない
答え・解説
B。false。 join()から戻る時点で対象スレッドは終了しています。そのためisAlive()はfalseです。なおjoin()にはInterruptedExceptionへの対応が必要です。
synchronized / lock object

Q214. 次の2メソッドが使うロックの組合せとして正しいものは？

class Gate {
    synchronized void enter() { }
    static synchronized void reset() { }
}
A. enter()もreset()も常にthis
B. enter()はthis、reset()はGate.class
C. enter()はGate.class、reset()はthis
答え・解説
B。 通常のsynchronizedインスタンスメソッドは対象インスタンスthisを、static synchronizedメソッドはクラスオブジェクトGate.classをロックします。
Thread.sleep / synchronized

Q215. 次の説明として正しいものは？

synchronized (lock) {
    Thread.sleep(100);
}
A. sleep中はlockのモニタを自動的に解放する
B. sleep中もlockのモニタを保持する
C. synchronized内ではsleepを呼べない
答え・解説
B。 Thread.sleepは現在のスレッドを休止しますが、保持しているモニタロックを解放しません。またInterruptedExceptionへの対応が必要です。

interface / default

Q56. 次のクラスCは、そのままではコンパイルできる？

interface A {
    default void show() { System.out.print("A"); }
}
interface B {
    default void show() { System.out.print("B"); }
}
class C implements A, B { }
A. できる。Aのshow()が優先される
B. できる。Bのshow()が優先される
C. できない
答え・解説
C。 同じシグネチャのdefaultメソッドを複数interfaceから継承すると競合するため、C側でshow()をオーバーライドして解決する必要があります。
final / override

Q57. 次のコードはコンパイルできる？

class Base {
    final void save() { }
}
class Child extends Base {
    void save() { }
}
A. できる
B. できない
答え・解説
B。 final メソッドはサブクラスでオーバーライドできません。final classが継承不可なのと同様に、final methodは再定義不可です。
private / inheritance

Q58. 次のChildのread()はコンパイルできる？

class Base {
    private int value = 7;
}
class Child extends Base {
    int read() { return value; }
}
A. できる
B. できない
答え・解説
B。 private メンバは宣言したクラスの外から直接参照できません。サブクラスでも同様です。必要ならprotected/publicのメソッドなどを介します。
constructor / void

Q59. 次のコードはどうなる？

class Coin {
    void Coin() { System.out.print("method"); }
}
Coin c = new Coin();
A. コンパイルエラー
B. コンパイルでき、何も表示されない
C. methodと表示される
答え・解説
B。 void Coin() はコンストラクタではなく通常のメソッドです。明示的なコンストラクタがないため、引数なしデフォルトコンストラクタが自動生成されます。
this / super

Q60. 次のコンストラクタはコンパイルできる？

class Child extends Parent {
    Child() {
        this(1);
        super();
    }
    Child(int n) { }
}
A. できる
B. できない
答え・解説
B。 明示的な this(...) または super(...) はコンストラクタの先頭に置きます。1つのコンストラクタで両方を直接呼ぶことはできません。
static / hiding

Q61. 出力は？

class Base {
    static String name() { return "Base"; }
}
class Child extends Base {
    static String name() { return "Child"; }
}
Base x = new Child();
System.out.println(x.name());
A. Base
B. Child
C. コンパイルエラー
答え・解説
A。Base。 staticメソッドはインスタンスメソッドのように動的ディスパッチされず、ここでは変数の宣言型Baseに基づいて解決されます。これはオーバーライドではなく隠蔽です。
List / set

Q62. 出力は？

List<String> xs = new ArrayList<>();
xs.add("A");
xs.add("B");
System.out.println(xs.set(1, "C"));
System.out.println(xs);
A. C / [A, C]
B. B / [A, C]
C. B / [A, B, C]
答え・解説
B。 set(index, value) は指定位置を置換し、置換前の要素を返します。要素数は増えません。
HashMap / null

Q63. 出力は？

Map<String, Integer> m = new HashMap<>();
m.put("A", null);
System.out.println(m.get("A"));
System.out.println(m.containsKey("A"));
System.out.println(m.containsKey("B"));
A. null / true / false
B. null / false / false
C. NullPointerException
答え・解説
A。 HashMapではvalueにnullを保持できます。get() がnullだけでは「未登録」か「nullを登録済み」か区別できませんが、containsKey() なら区別できます。
TreeSet / first last

Q64. 出力は？

TreeSet<Integer> s = new TreeSet<>();
s.add(8); s.add(3); s.add(5); s.add(3);
System.out.println(s.first() + ":" + s.last() + ":" + s.size());
A. 8:3:4
B. 3:8:3
C. 3:8:4
答え・解説
B。3:8:3。 TreeSetは重複を保持せず自然順序で管理します。最小値がfirst()、最大値がlast()です。
array / enhanced for

Q65. 出力は？

int[] a = {1, 2, 3};
for (int v : a) {
    v *= 10;
}
System.out.println(a[1]);
A. 2
B. 20
C. コンパイルエラー
答え・解説
A。2。 プリミティブ配列の拡張forで変数vに入るのは各要素の値のコピーです。vを書き換えても配列要素そのものは変わりません。
2次元配列 / default

Q66. 出力は？

int[][] table = new int[2][];
System.out.println(table.length);
System.out.println(table[0]);
A. 2 / null
B. 2 / []
C. NullPointerException
答え・解説
A。 外側の配列は長さ2で作られますが、各要素は int[] 型の参照で、まだ内側配列を作っていないため既定値nullです。
do-while / tracing

Q67. 出力は？

int n = 5;
do {
    System.out.print(n);
    n++;
} while (n < 5);
A. 何も表示されない
B. 5
C. 56
答え・解説
B。5。 do-whileは条件判定より先に本体を1回実行します。その後nは6になり、条件がfalseなので終了します。
nested loop / break

Q68. 出力は？

int count = 0;
for (int i = 0; i < 3; i++) {
    for (int j = 0; j < 3; j++) {
        if (j == 1) break;
        count++;
    }
}
System.out.println(count);
A. 1
B. 3
C. 6
答え・解説
B。3。 ラベルなしのbreakが終了するのは最も内側のループだけです。各iでj=0の1回だけcount++され、合計3回です。
instanceof / compile error

Q69. 次のコードはコンパイルできる？

String s = "java";
System.out.println(s instanceof Integer);
A. でき、falseと表示
B. でき、trueと表示
C. できない
答え・解説
C。 StringとIntegerは互いに継承関係がなく、どちらも別系統のfinalクラスです。この式は成立し得ない型関係なのでコンパイルエラーになります。
cast / inheritance

Q70. 出力は？

class Animal { }
class Dog extends Animal {
    void bark() { System.out.print("wan"); }
}
Animal a = new Dog();
Dog d = (Dog) a;
d.bark();
A. wan
B. ClassCastException
C. コンパイルエラー
答え・解説
A。wan。 aの宣言型はAnimalですが実体はDogです。Dogへのダウンキャストは実体型と整合するため成功します。
boolean / ||

Q71. 出力は？

int n = 0;
boolean ok = true || (++n > 0);
System.out.println(n + ":" + ok);
A. 0:true
B. 1:true
C. 1:false
答え・解説
A。0:true。 || は左辺がtrueなら右辺を評価しません。そのため ++n は実行されません。
boolean / &

Q72. 出力は？

int n = 0;
boolean ok = false & (++n > 0);
System.out.println(n + ":" + ok);
A. 0:false
B. 1:false
C. 1:true
答え・解説
B。1:false。 booleanに対する単一の & は両辺を評価します。左辺がfalseでも右辺の ++n が実行されます。短絡する && との違いに注意します。
Thread / start

Q73. 次のコードはどうなる？

Thread t = new Thread(() -> { });
t.start();
t.join();
t.start();
A. 同じThreadがもう一度開始される
B. 2回目のstart()でIllegalThreadStateException
C. コンパイルエラー
答え・解説
B。 1つのThreadオブジェクトをstart()できるのは1回だけです。終了済みでも再startはできず、実行時に IllegalThreadStateException になります。
Thread.sleep / lock

Q74. synchronizedブロック内でThread.sleep()した場合、保持中のモニタロックはどうなる？

A. sleep中は自動的に解放される
B. sleepしても保持したまま
C. synchronizedが解除されるためコンパイルエラー
答え・解説
B。 Thread.sleep() は現在のスレッドを一定時間休止させますが、保持しているモニタロックは解放しません。
static synchronized

Q75. static synchronizedメソッドが同期に使うロックとして正しいものは？

class Counter {
    static synchronized void inc() { }
}
A. 呼び出した各インスタンスのthis
B. Counter.classに対応するClassオブジェクト
C. 新しく作られた専用Threadオブジェクト
答え・解説
B。 通常のsynchronizedインスタンスメソッドはthisをロックしますが、static synchronized はそのクラスのClassオブジェクトをロックします。

interface / default / inheritance

Q336. 出力は？

interface Marked {
    default String mark() { return "I"; }
}
class Base {
    public String mark() { return "B"; }
}
class Child extends Base implements Marked { }

System.out.println(new Child().mark());
A. I
B. B
C. コンパイルエラー
答え・解説
B。B。クラスから継承したインスタンスメソッドとinterfaceのdefaultメソッドが競合する場合、クラス側のメソッドが優先されます。
interface / modifiers / compile error

Q337. コンパイルできる？

interface Meter {
    int value();
}
abstract class MeterBase implements Meter {
    abstract int value();
}
A. できる
B. できない
答え・解説
B。できません。interfaceのvalue()は暗黙にpublicです。実装・オーバーライド側でアクセス範囲をpackage-privateへ狭めることはできません。abstractメソッドでも同じです。
inheritance / final / overload

Q338. 出力は？

class Parent {
    final String pick(Number n) { return "P"; }
}
class Child extends Parent {
    String pick(Integer n) { return "C"; }
}

Parent p = new Child();
System.out.println(((Child)p).pick(1) + ":" + p.pick(1));
A. C:P
B. P:P
C. コンパイルエラー
答え・解説
A。C:P。finalは同じシグネチャのオーバーライドを禁止しますが、引数型が異なるpick(Integer)のオーバーロードは定義できます。どのオーバーロードを呼ぶかは参照型を基にコンパイル時に決まります。
constructor / this / initializer

Q339. 出力は？

class Note {
    { System.out.print("I"); }

    Note() {
        this(1);
        System.out.print("A");
    }
    Note(int n) {
        System.out.print("B");
    }
}

new Note();
A. IBA
B. BIA
C. IIBA
答え・解説
A。IBA。this(1)で同じオブジェクトの別コンストラクタへ委譲しても、インスタンス初期化子は1回だけ実行されます。初期化子I → 委譲先本体B → 呼出元本体Aの順です。
constructor / this / compile error

Q340. コンパイルできる？

class Book {
    Book() {
        System.out.print("A");
        this(10);
    }
    Book(int n) { }
}
A. できる
B. できない
答え・解説
B。できません。this(...)またはsuper(...)によるコンストラクタ呼び出しは、明示するならコンストラクタ本体の先頭文でなければなりません。
static / hiding / constructor

Q341. 出力は？

class Base {
    static String name() { return "B"; }
    Base() { System.out.print(name()); }
}
class Sub extends Base {
    static String name() { return "S"; }
}

new Sub();
A. B
B. S
C. コンパイルエラー
答え・解説
A。B。staticメソッドはオーバーライドではなく隠蔽です。Baseのコンストラクタ内のname()はBase.name()として静的に解決されます。
Map / getOrDefault / null

Q342. 出力は？

Map<String,Integer> map = new HashMap<>();
map.put("x", null);

System.out.println(
    map.getOrDefault("x", 9) + ":" +
    map.getOrDefault("y", 9)
);
A. 9:9
B. null:9
C. null:null
答え・解説
B。null:9。getOrDefault()はキーxが存在するため、そのキーに対応するnullを返します。存在しないyだけが既定値9になります。
List / Arrays.asList / backing array

Q343. 出力は？

String[] data = {"A", "B"};
List<String> list = Arrays.asList(data);

list.set(0, "X");
System.out.println(data[0] + ":" + list.get(0));
A. A:X
B. X:X
C. UnsupportedOperationException
答え・解説
B。X:X。Arrays.asList()のListは元配列を背後に持つ固定長ビューです。add/removeはできませんがsetは可能で、その変更は元配列にも反映されます。
Iterator / remove / runtime exception

Q344. 実行結果は？

List<String> list =
    new ArrayList<>(Arrays.asList("A", "B"));
Iterator<String> it = list.iterator();

it.next();
it.remove();
it.remove();

System.out.println(list);
A. []
B. [B]
C. IllegalStateExceptionが発生する
答え・解説
C。Iterator.remove()は直前のnext()で返した要素を削除します。同じnext()に対してremove()を2回続けて呼ぶことはできず、2回目でIllegalStateExceptionになります。
TreeSet / Comparator / equality

Q345. 出力は？

Set<String> set = new TreeSet<>(
    (a, b) -> Integer.compare(a.length(), b.length())
);
set.add("aa");
set.add("bb");
set.add("c");

System.out.println(set.size() + ":" + set.contains("zz"));
A. 3:true
B. 2:true
C. 2:false
答え・解説
B。2:true。TreeSetではComparatorが0を返す要素は同じ要素として扱われます。"aa"と"bb"は長さが同じため一方だけ保持され、"zz"も既存の長さ2の要素と比較して0になるためcontainsはtrueです。
array / jagged / runtime exception

Q346. 実行結果は？

int[][] data = new int[2][];
data[0] = new int[]{1, 2};

System.out.println(data[1].length);
A. 0
B. 2
C. NullPointerExceptionが発生する
答え・解説
C。2次元配列の各行は別々の配列参照です。data[1]には配列を代入していないため初期値nullのままで、lengthを参照するとNullPointerExceptionになります。
for / update expressions / array

Q347. 出力は？

int[] a = {1, 1, 1};

for (int i = 0; i < a.length; a[i] += i, i++) {
    // 本体は空
}

System.out.println(Arrays.toString(a));
A. [1, 2, 3]
B. [1, 1, 1]
C. [1, 2, 4]
答え・解説
A。[1, 2, 3]。forの更新部は左から順に実行されます。各周回でa[i]に現在のiを足してからi++するため、添字0,1,2へそれぞれ0,1,2が加算されます。
do-while / post-increment / trace

Q348. 出力は？

int n = 0;
int sum = 0;

do {
    sum += n;
} while (n++ < 3);

System.out.println(n + ":" + sum);
A. 3:3
B. 4:6
C. 4:10
答え・解説
B。4:6。本体では0,1,2,3を加算して6になります。条件のn++は比較後に必ず増加するため、最後の「3 < 3」がfalseになった時点でもnは4へ増えています。
instanceof / cast / null

Q349. 出力は？

Object obj = null;
boolean check = obj instanceof String;
String text = (String)obj;

System.out.println(check + ":" + (text == null));
A. false:true
B. true:true
C. NullPointerException
答え・解説
A。false:true。nullに対するinstanceofはfalseです。一方、参照型へのnullのキャスト自体は成功し、結果もnullなので例外にはなりません。
cast / runtime exception

Q350. 実行結果は？

Object obj = new StringBuilder("java");
String text = (String)obj;

System.out.println(text);
A. java
B. コンパイルエラー
C. ClassCastExceptionが発生する
答え・解説
C。objの宣言型はObjectなのでStringへのキャストはコンパイルできますが、実体はStringBuilderです。実行時の型がStringではないためClassCastExceptionになります。
boolean / operators / evaluation

Q351. 出力は？

int n = 0;
boolean result =
    (++n == 1) | (++n == 2) && (++n == 3);

System.out.println(result + ":" + n);
A. true:1
B. true:3
C. false:3
答え・解説
B。true:3。単一の|は短絡せず両辺を評価します。また|は&&より優先順位が高いので、最初の2条件を評価した結果trueに対して&&の右辺も評価されます。結果として3回すべて++nが実行されます。
Thread / interrupt status

Q352. 出力は？

Thread.currentThread().interrupt();

System.out.println(
    Thread.interrupted() + ":" +
    Thread.interrupted()
);
A. true:true
B. true:false
C. false:false
答え・解説
B。true:false。Thread.interrupted()は現在のスレッドの割り込み状態を返すと同時に、その状態をクリアします。1回目でtrueを取得してクリアされるため、2回目はfalseです。
Thread / synchronized / locks

Q353. 次の説明として正しいものは？

class Gate {
    synchronized void instanceTask() { /* ... */ }
    static synchronized void classTask() { /* ... */ }
}

Gate g = new Gate();
new Thread(g::instanceTask).start();
new Thread(Gate::classTask).start();
A. 2つは必ず同じロックを取り合う
B. instanceTaskはg、classTaskはGate.classをロックするため、同じロックとは限らない
C. static synchronizedはロックを使わない
答え・解説
B。通常のsynchronizedインスタンスメソッドはそのインスタンス（ここではg）をロックし、static synchronizedメソッドはクラスオブジェクトGate.classをロックします。
Thread / yield / scheduling

Q354. 出力順について正しいものは？

Thread t = new Thread(() -> {
    System.out.print("B");
    Thread.yield();
    System.out.print("C");
});

t.start();
System.out.print("A");
A. 必ずBAC
B. 必ずABC
C. ABC・BAC・BCAなどがあり得て、yield()だけでは順序を保証できない
答え・解説
C。yield()は他スレッドへ実行機会を譲るヒントにすぎず、切り替えを保証しません。スレッドt内ではBがCより先ですが、Aがどこに入るかは固定されません。
constructor / overload / compile error

Q355. コンパイルできる？

class Token {
    Token(String s) { }
    Token(Integer n) { }
}

Token t = new Token(null);
A. String版が選ばれてコンパイルできる
B. Integer版が選ばれてコンパイルできる
C. どちらがより適合するか決められずコンパイルエラー
答え・解説
C。nullはStringにもIntegerにも渡せますが、StringとIntegerの間に「より具体的」と決められる継承関係がありません。そのためコンストラクタ呼び出しが曖昧になりコンパイルエラーです。

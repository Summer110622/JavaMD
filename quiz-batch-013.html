interface / modifiers / compile error

Q256. 次のMeterはコンパイルできる？

interface Left {
    int LEVEL = 1;
}
interface Right {
    int LEVEL = 2;
}
class Meter implements Left, Right {
    int read() {
        return LEVEL;
    }
}
A. でき、1を返す
B. でき、2を返す
C. できない
答え・解説
C。両方のinterfaceから同名の定数LEVELが見えるため、単純名だけではどちらか決められません。Left.LEVELやRight.LEVELのように修飾すれば参照できます。
inheritance / override / modifiers

Q257. 出力は？

class Parent {
    protected Number value() { return 1; }
}
class Child extends Parent {
    @Override
    public Integer value() { return 2; }
}

System.out.println(new Child().value() + 1);
A. 2
B. 3
C. コンパイルエラー
答え・解説
B。3。オーバーライドではアクセス範囲を広げることができ、戻り値も親の戻り値型のサブタイプにできます。IntegerはNumberのサブタイプなので有効です。
interface / abstract / inheritance

Q258. 次のコードはコンパイルできる？

interface Pair {
    void first();
    void second();
}
abstract class Half implements Pair {
    public void first() { }
}
class Full extends Half {
    public void second() { }
}

Full x = new Full();
A. できる
B. Halfがsecond()を実装していないのでできない
答え・解説
A。abstractクラスはinterfaceの抽象メソッドをすべて実装しなくても構いません。最終的な具象クラスFullが残りのsecond()を実装しているため、Fullは生成できます。
constructor / override / trace

Q259. 出力は？

class Parent {
    Parent() {
        System.out.print(value());
    }
    int value() { return 1; }
}
class Child extends Parent {
    int n = 7;
    @Override
    int value() { return n; }
}

new Child();
A. 0
B. 1
C. 7
答え・解説
A。0。Parentのコンストラクタから呼ばれたvalue()も実体がChildなのでChild版へ動的ディスパッチされます。ただしその時点ではChildのフィールド初期化n = 7がまだ実行されておらず、intの既定値0です。
constructor / this / super / compile error

Q260. 次のBoxはコンパイルできる？

class Box {
    Box() {
        this(1);
        super();
    }
    Box(int n) { }
}
A. できる
B. できない
答え・解説
B。コンストラクタの明示的なthis(...)またはsuper(...)は先頭文でなければならず、同じコンストラクタ本体で両方を順に呼ぶことはできません。
constructor / this / static

Q261. 出力は？

class Ticket {
    static int next;
    int id;

    Ticket() {
        this(++next);
    }
    Ticket(int id) {
        this.id = id;
    }
}

Ticket a = new Ticket();
Ticket b = new Ticket();
System.out.println(Ticket.next + ":" + b.id);
A. 1:1
B. 2:1
C. 2:2
答え・解説
C。引数なしコンストラクタを呼ぶたびにstatic変数nextを先にインクリメントし、その値を別コンストラクタへ渡します。2個目のTicketではnextもidも2です。
static / inheritance / trace

Q262. 出力は？

class Parent {
    static String who() { return "P"; }
}
class Child extends Parent {
    static String who() { return "C"; }
}

Parent x = new Child();
System.out.println(x.who() + ":" + Child.who());
A. P:C
B. C:C
C. P:P
答え・解説
A。P:C。staticメソッドはインスタンスメソッドのようにオーバーライドされず、参照時の型に基づいて選ばれます。xの宣言型はParentなので最初はPです。
Map / keySet / view

Q263. 出力は？

Map<String,Integer> map = new HashMap<>();
map.put("a", 1);
map.put("b", 2);

Set<String> keys = map.keySet();
keys.remove("a");

System.out.println(map.size() + ":" + map.containsKey("a"));
A. 2:true
B. 1:false
C. 1:true
答え・解説
B。keySet()はMapから独立したコピーではなく、Mapに結び付いたビューです。keySet側でキーを削除すると対応するMapのエントリも削除されます。
Map / putIfAbsent / null

Q264. 出力は？

Map<String,Integer> map = new HashMap<>();
map.put("x", null);
map.putIfAbsent("x", 5);

System.out.println(map.get("x"));
A. null
B. 5
C. NullPointerException
答え・解説
B。HashMapのputIfAbsentは、キーが未登録の場合だけでなく、現在の値がnullの場合にも指定値を関連付けます。そのためxの値は5になります。
TreeSet / Comparator / Set

Q265. 出力は？

Set<String> set = new TreeSet<>(
    (a, b) -> Integer.compare(a.length(), b.length())
);

System.out.println(set.add("aa"));
System.out.println(set.add("bb"));
System.out.println(set);
A. true / true / [aa, bb]
B. true / false / [aa]
C. false / false / []
答え・解説
B。TreeSetはComparatorの比較結果が0なら同じ要素として扱います。aaとbbは文字数が同じなので2回目のaddはfalseとなり、最初のaaだけが残ります。

array / covariance / runtime error

Q267. 次のコードはどうなる？

Number[] values = new Integer[2];
values[0] = 1;
values[1] = 2.5;

System.out.println(values[1]);
A. 2.5と表示
B. コンパイルエラー
C. 実行時にArrayStoreException
答え・解説
C。配列は共変なのでInteger[]をNumber[]変数へ代入すること自体は可能です。しかし実体はInteger[]のため、Doubleである2.5を格納しようとすると実行時にArrayStoreExceptionになります。
array / labeled continue / loop

Q268. 出力は？

int[][] data = { {1, 2}, {3}, {4, 5} };
int sum = 0;

outer:
for (int[] row : data) {
    for (int n : row) {
        if (n == 3) continue outer;
        sum += n;
    }
}

System.out.println(sum);
A. 9
B. 12
C. 15
答え・解説
B。最初の行で1+2、2行目は3に到達すると外側ループの次反復へ移るため加算なし、最後の行で4+5です。合計は12です。
for / continue / trace

Q269. 出力は？

int n = 0;
for (int i = 0; i < 5; i++, n += 10) {
    if (i == 2) continue;
    n += i;
}

System.out.println(n);
A. 38
B. 48
C. 58
答え・解説
C。for文でcontinueしても更新式は実行されます。i=2の本体加算だけを飛ばし、各反復後のn += 10は5回実行されます。ほかのiの加算0+1+3+4=8と合わせて58です。

cast / interface / runtime error

Q271. 次のコードはどうなる？

interface Flag { }
class Marked implements Flag { }
class Plain { }

Object x = new Plain();
Flag f = (Flag) x;
System.out.println(f);
A. コンパイルエラー
B. コンパイルできるが実行時にClassCastException
C. 正常にPlainの文字列表現を表示
答え・解説
B。宣言型Objectからinterface型への明示的キャストはコンパイルできますが、実体PlainはFlagを実装していません。実行時の型検査でClassCastExceptionになります。
boolean / short-circuit / trace

Q272. 出力は？

int[] count = {0};
boolean a = false && (++count[0] > 0);
boolean b = false & (++count[0] > 0);

System.out.println(count[0] + ":" + a + ":" + b);
A. 0:false:false
B. 1:false:false
C. 2:false:false
答え・解説
B。&&は左辺がfalseなら右辺を評価しません。一方、booleanに対する&は両辺を評価するため、2つ目の式だけでcountが1増えます。どちらの結果もfalseです。
Thread / interrupt / state

Q273. 出力は？

Thread.currentThread().interrupt();

boolean a = Thread.currentThread().isInterrupted();
boolean b = Thread.interrupted();
boolean c = Thread.currentThread().isInterrupted();

System.out.println(a + ":" + b + ":" + c);

Thread / synchronized / locks

Q274. 次の2メソッドのロックについて正しいものは？

class Gate {
    synchronized void instanceWork() { }
    static synchronized void classWork() { }
}

Gate g = new Gate();
A. g.instanceWork()とGate.classWork()は必ず同じロックを使う
B. 前者はg自身、後者はGate.classをロックするため別のロック
C. static synchronizedはロックを使わない
答え・解説
B。通常のsynchronizedインスタンスメソッドはthisを、static synchronizedメソッドはそのクラスのClassオブジェクトをロックします。この2つは別のモニタです。
Thread / sleep / synchronized

Q275. pause(...)のsleep中、lockについて正しい説明は？

static void pause(Object lock) throws InterruptedException {
    synchronized (lock) {
        Thread.sleep(200);
    }
}
A. sleep中はlockを自動的に解放する
B. sleep中もlockを保持したまま
C. synchronized内ではsleepを呼べない
答え・解説
B。Thread.sleep()は現在のスレッドを一時停止させますが、保持しているモニタロックは解放しません。この例ではthrows InterruptedExceptionでchecked例外にも対応しています。

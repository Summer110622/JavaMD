Deep Dive · Java Platform

Java / JVM / JDK を詳しく

ソースから実行まで

.java にソースを書く。
javac がバイトコードの .class に変換する。
JVM がクラスをロードし、バイトコードを実行する。
用語役割初心者が混同しやすい点
JDK開発用ツール一式javac などを含む
JVMバイトコードを実行Javaソースを直接実行するものではない

Deep Dive · Syntax

変数・型・演算子を詳しく

プリミティブ型と参照型

int や boolean は値そのものを扱うプリミティブ型です。String、配列、クラスのインスタンスは参照型で、変数にはオブジェクトへの参照が入ります。

参照の共有
StringBuilder a = new StringBuilder("A");
StringBuilder b = a;
b.append("B");
System.out.println(a); // AB

== と equals

プリミティブ型の == は値比較です。参照型の == は同じオブジェクトを指すかを比較します。内容比較は、その型が提供する equals() を使います。

暗黙の型変換とキャスト

数値変換
int n = 10;
long x = n;        // widening: 自動
int y = (int) x;  // narrowing: 明示キャスト

インクリメント

前置・後置
int i = 1;
int a = i++; // a=1, i=2
int b = ++i; // i=3, b=3
試験で注意: 代入式、前置/後置インクリメント、短絡評価が組み合わさると追跡ミスが起きやすくなります。
Deep Dive · Control Flow

if / switch / for / while を詳しく

if はboolean式だけ

Javaの if 条件には必ず boolean が必要です。C系言語のように数値を真偽として扱えません。

&& と || の短絡評価

short-circuit
String s = null;
if (s != null && s.length() > 0) {
    System.out.println(s);
}

&& は左がfalseなら右を評価しません。|| は左がtrueなら右を評価しません。

for の評価順序

for (初期化; 条件; 更新) は「初期化 → 条件 → 本体 → 更新 → 条件…」の順です。continue でも更新式へ進みます。

break / continue

命令意味
break現在のループまたはswitchを終了
continue現在回の残りを飛ばして次の反復へ
Deep Dive · OOP

クラス・オブジェクト・this・static を詳しく

クラスとインスタンス

クラスは設計図、インスタンスは実体です。インスタンスフィールドは各オブジェクトごとに別々、static フィールドはクラス全体で共有されます。

instance vs static
class Counter {
    int value;          // 各インスタンスに1つ
    static int total;   // クラスに1つ
}

this

this は「現在のインスタンス」を指します。static メソッドには現在のインスタンスがないため this は使えません。

オーバーロード

同じメソッド名でも引数リストが異なれば複数定義できます。戻り値だけ違う定義はオーバーロードになりません。

カプセル化

フィールドを private にして、必要な操作だけメソッド経由で公開すると、不正な状態変更を防ぎやすくなります。

Deep Dive · Exceptions / Generics

例外とGenericsを詳しく

checked / unchecked

分類例特徴
checkedIOException捕捉またはthrows宣言が必要
uncheckedNullPointerException, IllegalArgumentExceptionコンパイラが捕捉を強制しない

try / catch / finally

finally は通常、成功・失敗にかかわらず後処理を行う場所です。ファイルやストリームは try-with-resources を優先します。

try-with-resources
try (var reader = Files.newBufferedReader(path)) {
    System.out.println(reader.readLine());
}

Generics

List<String> のように要素型を型パラメータとして指定し、コンパイル時に型安全性を高めます。

注意: List<Dog> は List<Animal> のサブタイプではありません。Genericsは基本的に不変です。
Deep Dive · Collections

Collection Framework を詳しく

まず「順序」「重複」「キー」を見る

型順序重複用途
Listありあり順番付きデータ
Set実装によるなし一意な集合
Map実装によるkeyは一意key→value
Queue/Dequeありあり得る処理待ち・両端操作

実装を選ぶ基準

ArrayList は添字アクセスに強く、HashSet/HashMap は平均的に高速な検索、TreeSet/TreeMap はソート順を保ちます。

Deep Dive · List

Listを詳しく

Listは順序を持ち、同じ値を複数保持できます。添字は0から始まります。

removeの違い
List<Integer> list = new ArrayList<>(List.of(10, 20, 30));
list.remove(1);                  // index 1 を削除 → 20
list.remove(Integer.valueOf(30)); // 値30を削除
重要: List<Integer> では remove(1) が「値1」ではなく「index 1」の削除になる点が典型的なひっかけです。

途中の要素を削除すると後続要素のindexが詰まるため、indexで走査しながら削除する場合は増分を慎重に扱います。

Deep Dive · Set / Map

Set・TreeSet・Map・HashMapを詳しく

HashSet

重複要素を保持しません。反復順序は保証されません。

TreeSet

重複を除外し、自然順序またはComparatorによる順序で保持します。first()、last()、lower()、higher() などのナビゲーション操作が使えます。

HashMap

同じkeyは上書き
Map<String, Integer> map = new HashMap<>();
map.put("A", 10);
map.put("A", 20);
System.out.println(map.size());   // 1
System.out.println(map.get("A")); // 20

同じkeyへの put は要素数を増やさず、valueを置き換えます。HashMapの反復順序は保証されません。

Deep Dive · Lambda

ラムダ式を詳しく

ラムダ式は「処理をオブジェクトとして渡す」ための簡潔な記法です。ラムダ式単体に型があるのではなく、代入先や引数位置から対象となる関数型interfaceが決まります。

基本形

lambda syntax
() -> System.out.println("run")
x -> x * 2
(a, b) -> a + b
(String s) -> s.length()

式ラムダとブロックラムダ

expression / block
Function<String, Integer> a = s -> s.length();
Function<String, Integer> b = s -> {
    int n = s.length();
    return n;
};

式が1つなら中括弧と return を省略できます。ブロック形式で値を返すなら return が必要です。

関数型interface

抽象メソッドを1つだけ持つinterfaceを関数型interfaceとしてラムダの対象にできます。default や static メソッドがあっても、抽象メソッドが1つなら利用できます。

effectively final

captured local variable
int base = 10;
Function<Integer, Integer> add = x -> x + base;
// base = 20; // 再代入するとラムダから参照できない

ラムダから参照するローカル変数は final または effectively final である必要があります。

this の意味

ラムダ式の this はラムダ自身ではなく、ラムダを囲んでいるインスタンスの this です。匿名クラスとは挙動が異なります。

メソッド参照

形例
static methodInteger::parseInt
特定インスタンスのmethodSystem.out::println
任意インスタンスのmethodString::length
constructorArrayList::new
読み方: ラムダ問題では「入力型」「戻り値型」「副作用の有無」の3点を先に確認します。
Deep Dive · Functional Interface

Predicate / Function / Consumer / Supplier を詳しく

interface抽象メソッド入力→出力典型用途
Predicate<T>testT → boolean条件判定
Function<T,R>applyT → R変換
Consumer<T>acceptT → void消費・出力
Supplier<T>get() → T生成

合成

compose
Predicate<String> notBlank = s -> !s.isBlank();
Predicate<String> longEnough = s -> s.length() >= 3;
Predicate<String> valid = notBlank.and(longEnough);

Function<String, String> trim = String::trim;
Function<String, Integer> len = String::length;
Function<String, Integer> trimThenLen = trim.andThen(len);

Predicate は and/or/negate、Function は andThen/compose で処理を組み合わせられます。

Deep Dive · Stream

Stream APIを詳しく

Streamはコレクションそのものではなく、データ列に対する処理パイプラインです。元のListを自動で書き換えるものではありません。

中間操作と終端操作

分類例特徴
中間操作filter, map, sorted, distinctStreamを返す。遅延評価
終端操作toList, count, forEach, collect処理を実行して結果を確定
pipeline
List<String> result = names.stream()
    .filter(s -> !s.isBlank())
    .map(String::trim)
    .filter(s -> s.length() >= 3)
    .sorted()
    .toList();

map と flatMap

map は1要素を1要素へ変換します。flatMap は「各要素からStreamを作り、それを1本に平坦化」します。

reduce

reduce
int total = numbers.stream()
    .reduce(0, Integer::sum);

Streamは再利用できない

終端操作を一度行ったStreamをもう一度使うと IllegalStateException になります。必要なら元コレクションから新しいStreamを作ります。

試験で注意: filter は要素を残す/落とす、map は要素を変換、forEach は終端操作です。
Deep Dive · Date/Time / Files

java.time と Filesを詳しく

LocalDate / LocalDateTime / Instant

型表すもの
LocalDate日付のみ。タイムゾーンなし
LocalDateTime日付+時刻。タイムゾーンなし
InstantUTC基準の時点
ZonedDateTimeタイムゾーン込みの日時

java.time の主要クラスは不変です。plusDays() などは元オブジェクトを書き換えず、新しい値を返します。

immutable
LocalDate d1 = LocalDate.of(2026, 9, 11);
LocalDate d2 = d1.plusDays(1);
// d1 は 2026-09-11 のまま

Path / Files

Path はパスを表し、Files は読み書き・存在確認・ディレクトリ操作などを提供します。I/Oでは IOException を意識します。

Deep Dive · Thread

Thread / Runnable / synchronized を詳しく

start と run

start vs run
Thread t = new Thread(() -> System.out.println("worker"));
t.start(); // 新しいスレッドを開始
// t.run(); // 単なるメソッド呼び出し

sleep / join / yield

API意味
sleep(ms)現在のスレッドを一定時間休止
join()対象スレッドの終了を待つ
yield()実行権を他スレッドへ譲るヒント。保証ではない

共有データと競合

複数スレッドが同じ可変データを同時更新すると、読み書きが競合することがあります。

synchronized
class Counter {
    private int value;
    synchronized void increment() {
        value++;
    }
}

synchronized は同じモニタを使う同期区間への同時侵入を制御します。ただし、並行処理設計全体が自動で安全になるわけではありません。

InterruptedException

sleep や join は割り込みを受ける可能性があり、InterruptedException を扱う必要があります。

初心者向け順序: まず new Thread(task) → start() → 必要なら join()。その後に共有状態と同期を学ぶと整理しやすいです。
Deep Dive · Exam Reading

コード読解の共通チェック手順

コンパイル可能か — 型、アクセス修飾子、継承、コンストラクタ、returnを確認。
変数の型を分ける — 宣言型と実体型を区別。
評価順序を追う — 代入、前置/後置、短絡評価、ループ更新。
コレクションの性質を適用 — Listは順序、Setは重複なし、Mapは同じkeyを上書き。
ラムダの入出力型を確認 — Predicate/Function/Consumer/Supplierを判定。
Streamの終端操作まで追う — 中間操作だけでは結果は確定しない。
Threadはstartかrunかを見る — 新規スレッド開始か単なる呼び出しかを区別。

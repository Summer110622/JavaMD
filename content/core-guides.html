Start · Runtime

1. Java / JVM / JDK を仕組みから理解する

Javaでは、書いたソースコードをそのままOSが実行するのではなく、まず javac でバイトコードへコンパイルし、そのバイトコードをJVMが実行します。初心者の段階では「JDKで作る → JVMで動く」という流れを押さえると、コンパイルエラーと実行時エラーを区別しやすくなります。

用語役割覚えるポイント
JDK開発キットjavac など開発用ツールを含む
JVMJavaバイトコードの実行環境.class の命令を実行する
バイトコードJVM向けの中間命令通常は .class ファイルに格納
JAR複数のclassやリソースをまとめる形式ライブラリ配布などで使う
コンパイルと実行
javac Hello.java
java Hello

javac が成功すれば、基本的には Hello.class が生成されます。java Hello では拡張子 .class を付けません。

コンパイル時と実行時を分ける

コンパイル時

型不一致、未定義変数、アクセス違反、構文エラーなどを検査。

実行時

NullPointerException、ClassCastException など、実際に動かしたときに起きる問題。

mainメソッド

エントリーポイント
public static void main(String[] args) {
    System.out.println("start");
}

Javaアプリケーションを通常の方法で起動すると、JVMはこの形の main を入口として探します。static なので、起動時にオブジェクトを作らなくても呼び出せます。

試験での見方: 「コンパイルできるか」「起動できるか」「起動後に例外が出るか」は別問題です。順番に判定します。
Language · Types

2. 基本構文・変数・型・配列

プリミティブ型と参照型

分類代表特徴
プリミティブ型byte short int long float double char boolean値そのものを扱う
参照型String、配列、クラス、interfaceオブジェクトへの参照を扱い、null を取り得る

数値リテラルと型変換

拡大変換と縮小変換
int a = 10;
long b = a;        // 拡大変換: 自動
long c = 100L;
int d = (int) c;   // 縮小変換: 明示的キャスト

小さい範囲の整数型から大きい範囲へは自動変換できる場合がありますが、情報が失われる可能性がある方向では明示的キャストが必要です。

演算時の昇格: byte や short 同士の算術演算でも結果が通常 int になる点は頻出です。

final と var

変数宣言
final int LIMIT = 10;
var name = "Java";   // String と推論

final 変数は一度代入した参照・値を再代入できません。参照型の場合、参照先オブジェクトの内部まで自動的に不変になるわけではありません。var はローカル変数で使用でき、右辺から型が推論されます。

String は不変

String
String s = "java";
s.toUpperCase();
System.out.println(s); // java
s = s.toUpperCase();
System.out.println(s); // JAVA

String のメソッドは元の文字列を書き換えず、新しい文字列を返すものが多いです。内容比較は equals()、参照比較は == です。

配列

1次元・2次元配列
int[] nums = {10, 20, 30};
System.out.println(nums.length); // 3

int[][] table = new int[2][];
table[0] = new int[]{1, 2};
table[1] = new int[]{3, 4, 5};

Javaの2次元配列は「配列の配列」です。各行の長さは同じでなくても構いませんし、行そのものが null のこともあります。配列は length フィールド、String は length() メソッドという違いにも注意します。

ラッパークラスとオートボクシング

Integer
Integer x = 10; // int → Integer
int y = x;      // Integer → int

Collectionsはプリミティブ型を型引数にできないため、List<Integer> のようにラッパークラスを使います。

Language · Control Flow

3. if / switch / loop / boolean式

if と比較

if
if (score >= 80) {
    System.out.println("A");
} else if (score >= 60) {
    System.out.println("B");
} else {
    System.out.println("C");
}

Javaの if 条件は boolean でなければなりません。C系言語のように if (1) は書けません。

&& と || は短絡評価

short-circuit
String text = null;
if (text != null && text.length() > 0) {
    System.out.println(text);
}

&& は左がfalseなら右を評価せず、|| は左がtrueなら右を評価しません。nullチェックや安全なキャスト判定で重要です。& / | はbooleanにも使えますが、両辺を評価します。

代入式と比較式

= と ==
boolean flag = true;
if (flag = false) {    // 代入。式の値は false
    System.out.println("x");
}
if (flag == false) {   // 比較
    System.out.println("y");
}

switch式

Java 17 switch
String label = switch (day) {
    case 1 -> "Mon";
    case 2 -> "Tue";
    default -> "Other";
};

矢印形式では従来の case: のような意図しないフォールスルーを避けられます。ブロックから値を返す場合は yield を使います。

for / 拡張for / while

loop
for (int i = 0; i < list.size(); i++) {
    System.out.println(list.get(i));
}

for (String s : list) {
    System.out.println(s);
}

int n = 0;
while (n < 3) {
    n++;
}

break はループを終了し、continue は現在の反復の残りを飛ばして次へ進みます。Listをindexで削除しながら走査すると要素が左へ詰まるため、indexの増分に注意します。

4. クラス・オブジェクト・this・static・interface

クラスは設計、オブジェクトは実体

interface

record は主にデータ保持用の型を簡潔に宣言する仕組み、enum は有限個の定数候補を型安全に表す仕組みです。どちらも通常のクラス同様にメソッドを持てます。

Language · Exceptions & Generics

6. 例外・try/catch・Generics

checked例外とunchecked例外

分類例特徴
checkedIOExceptioncatchするかthrows宣言が必要
uncheckedNullPointerException, IllegalArgumentExceptionコンパイラはcatchを強制しない

throw と throws

例外を投げる
void load() throws IOException {
    if (bad) {
        throw new IOException("failed");
    }
}

throw は例外オブジェクトを実際に投げ、throws はメソッド宣言で「この例外を呼出し側へ伝える可能性がある」と示します。

try / catch / finally

例外処理
try {
    int n = Integer.parseInt(text);
} catch (NumberFormatException e) {
    System.out.println("数字ではありません");
} finally {
    System.out.println("終了処理");
}

finally は原則として正常終了・例外発生のどちらでも実行されます。リソース解放には try-with-resources を優先します。

Genericsの目的

型安全なList
List<String> names = new ArrayList<>();
names.add("Alice");
String name = names.get(0);

Genericsは「中に入る型」をコンパイル時に制約し、不要なキャストや実行時の型エラーを減らします。

型パラメータとワイルドカード

extends / super wildcard
List<? extends Number> src;
List<? super Integer> dest;

? extends Number は主にNumberとして読み出す側、? super Integer はIntegerを書き込む側で使います。覚え方はPECS（Producer Extends, Consumer Super）です。

不変性: List<Integer> は List<Number> のサブタイプではありません。
Collections

7. Collection Framework 全体像

Collection Frameworkでは、目的に応じて「順序」「重複」「キー検索」「取り出し方向」を先に決めると選択しやすくなります。

目的代表主な特徴
順番付き一覧ArrayList重複可・indexあり
重複排除HashSet平均O(1)検索
ソート済み集合TreeSet自然順序/Comparator
キー→値HashMapキー重複不可・値は上書き
FIFO / StackArrayDeque両端操作が高速

equals と hashCode

HashSet や HashMap は、要素・キーの同一性判定に equals() と hashCode() を使います。値オブジェクトで equals() をオーバーライドするなら、通常 hashCode() も整合するように実装します。

Comparable と Comparator

Comparable

型自身が「自然順序」を定義。compareTo。

Comparator

外部から並び順を与える。複数の並び方を使い分けやすい。

複雑度は目安: Hash系の検索は平均O(1)、Tree系はO(log n)、ArrayListのindex取得はO(1)が代表的です。
Collections · List

8. List — ArrayList / LinkedList / removeの罠

ArrayList

連続したindexで要素を扱う用途の第一候補です。末尾追加やindex参照は扱いやすい一方、中間の挿入・削除では後続要素の移動が発生します。

ArrayList
List<String> names = new ArrayList<>();
names.add("A");
names.add("B");
names.set(1, "C");
System.out.println(names.get(0));

remove(int) と remove(Object)

Integer Listの注意
List<Integer> nums = new ArrayList<>(List.of(10, 20, 30));
nums.remove(1);                 // index 1 を削除 → 20
nums.remove(Integer.valueOf(30)); // 値 30 を削除

List<Integer> では数値リテラルがindex版に解決されることがあるため、値削除では Integer.valueOf を明示すると安全です。

削除しながら走査

拡張for中に構造変更すると ConcurrentModificationException の原因になります。条件削除なら removeIf や Iterator.remove() を検討します。

List.of

List.of(...) が返すListは変更不可です。add や remove を行うと UnsupportedOperationException になります。

Collections · Set

9. Set — HashSet / LinkedHashSet / TreeSet

Setは「同じ要素を複数保持しない」集合です。どの順序を必要とするかで実装を選びます。

実装順序特徴
HashSet保証なし平均O(1)の検索
LinkedHashSet挿入順順序も維持したい場合
TreeSetソート順O(log n)、範囲検索も可能

TreeSetの代表API

NavigableSet
TreeSet<Integer> set = new TreeSet<>(List.of(10, 20, 30));
set.first();      // 10
set.last();       // 30
set.lower(20);    // 10
set.higher(20);   // 30
set.floor(25);    // 20
set.ceiling(25);  // 30

TreeSet では要素同士を比較できる必要があります。自然順序がない型ならComparatorを与えます。

Collections · Map

10. Map — HashMap / TreeMap / compute / merge

Mapはキーと値の対応を保持します。キーは重複できず、同じキーへ put すると値が上書きされます。

基本操作
Map<String, Integer> scores = new HashMap<>();
scores.put("A", 10);
scores.put("A", 20); // 上書き
System.out.println(scores.size());   // 1
System.out.println(scores.get("A")); // 20

存在判定

get(key) == null だけでは「キーがない」のか「null値が入っている」のか区別できない場合があります。必要なら containsKey を使います。

entrySetで走査

Map.Entry
for (Map.Entry<String, Integer> e : scores.entrySet()) {
    System.out.println(e.getKey() + ":" + e.getValue());
}

computeIfAbsent と merge

集計・初期化
Map<String, List<String>> groups = new HashMap<>();
groups.computeIfAbsent("A", k -> new ArrayList<>()).add("x");

Map<String, Integer> counts = new HashMap<>();
counts.merge("apple", 1, Integer::sum);

TreeMap はキー順に保持します。キー比較可能性の条件はTreeSetと同様です。

Queueは先入れ先出し（FIFO）、Dequeは両端キューです。ArrayDeque はQueue用途にもStack用途にも使えます。

Functional · Lambda

12. ラムダ式を詳しく — 型推論・effectively final・メソッド参照

ラムダ式は「処理を値として渡す」ための構文です。ただしラムダ式単独に独立した型があるのではなく、代入先や引数位置から決まる関数型interfaceがターゲット型になります。

基本構文

lambda syntax
Predicate<String> p1 = s -> s.isBlank();
Predicate<String> p2 = (String s) -> s.isBlank();
Function<String, Integer> len = s -> s.length();
Consumer<String> print = s -> System.out.println(s);
Supplier<String> hello = () -> "hello";

引数が1つで型を省略する場合は丸括弧も省略できます。複数引数では括弧が必要です。処理が1式なら波括弧・return を省略できます。

ブロックラムダ

block lambda
Function<Integer, Integer> doubleIt = n -> {
    int result = n * 2;
    return result;
};

値を返す関数型interfaceでブロック本体を使う場合、必要な経路で値を返さなければコンパイルエラーになります。

effectively final

ローカル変数のキャプチャ
int limit = 3;
Predicate<String> longEnough = s -> s.length() >= limit;
// limit = 5; // これを書くと effectively final でなくなり、ラムダから参照不可

ラムダから参照するローカル変数は、final と明記されているか、初期化後に再代入されないeffectively finalである必要があります。フィールドにはこの制約はありません。

ラムダ内の this

ラムダ式は匿名クラスと異なり、独自の this を作りません。ラムダ内の this は、それを囲むインスタンスの this を指します。

メソッド参照

種類例対応するイメージ
staticInteger::parseInts -> Integer.parseInt(s)
特定インスタンスSystem.out::printlnx -> System.out.println(x)
任意インスタンスString::lengths -> s.length()
コンストラクタArrayList::new() -> new ArrayList<>()

ターゲット型が必要

target typing
// var f = x -> x + 1; // ラムダだけでは型を決められない
Function<Integer, Integer> f = x -> x + 1;

例外とラムダ

ラムダ本体からchecked例外を外へ投げられるかは、ターゲットとなる関数型interfaceの抽象メソッドの throws 宣言に依存します。標準の Function などは一般にchecked例外を宣言していません。

検定での見方: まず「どの関数型interfaceに代入されるか」を確定し、その抽象メソッドの引数型・戻り値型とラムダ本体が一致するかを確認します。

13. 標準の関数型interfaceを使い分ける

型形代表メソッド用途

Functional · Stream

14. Stream API — パイプライン・遅延評価・終端操作

StreamはCollectionそのものではなく、要素列に対する処理パイプラインです。元データ → 中間操作 → 終端操作という形で考えます。

pipeline
List<String> result = names.stream()
    .filter(s -> !s.isBlank())
    .map(String::trim)
    .map(String::toUpperCase)
    .distinct()
    .sorted()
    .toList();

中間操作と終端操作

中間操作終端操作
filter, map, flatMap, distinct, sorted, limittoList, collect, count, forEach, reduce, findFirst

中間操作は基本的に遅延評価され、終端操作が呼ばれるまで処理が実行されません。Streamは一度終端操作すると再利用できません。

map と flatMap

flatMap
List<List<String>> nested = List.of(List.of("A", "B"), List.of("C"));
List<String> flat = nested.stream()
    .flatMap(List::stream)
    .toList();

reduce

合計
int sum = List.of(1, 2, 3).stream()
    .reduce(0, Integer::sum);

collect と groupingBy

groupingBy
Map<Integer, List<String>> byLength = names.stream()
    .collect(Collectors.groupingBy(String::length));

Optional

findFirst() や引数なし reduce() などは、結果が存在しない可能性を表す Optional を返します。無条件に get() するより、orElse、orElseGet、ifPresent などを使います。

副作用を減らす

map や filter の中で外部状態を書き換えると追跡が難しくなります。特にparallel streamでは共有可変状態が競合の原因になります。

頻出: map は「要素を別の値へ変換」、filter は「要素を残すか捨てるか」、forEach は終端操作です。

Practical · Thread

16. Thread API — start / run / sleep / join / synchronized

Threadを開始する

Thread + Runnable
Thread worker = new Thread(() -> {
    System.out.println("worker");
});
worker.start();
worker.join();

start() は新しいスレッドを開始し、その新しいスレッド上で run() が呼ばれます。run() を直接呼ぶだけでは通常のメソッド呼出しです。

代表API

API意味
start()新しいスレッドを開始
sleep(ms)現在実行中のスレッドを一定時間休止
join()対象スレッドの終了を待つ
interrupt()割り込みを要求
currentThread()現在のThreadを取得
isAlive()開始済みでまだ終了していないか

sleepは誰を止める？

Thread.sleep(...) はstaticメソッドで、呼出し元の現在のスレッドを休止します。Threadインスタンスを指定して別スレッドを眠らせるAPIではありません。

競合状態

共有状態
class Counter {
    private int value;

    synchronized void increment() {
        value++;
    }
}

複数スレッドが同じ可変データを同時更新すると、読み取り→計算→書き込みが割り込まれて期待と違う結果になることがあります。synchronized は排他制御と可視性を提供する基本手段です。

interrupt

interrupt() は強制終了ではなく割り込み要求です。sleep や join 中なら InterruptedException で通知される場合があります。

実行順序

重要: 複数スレッドの出力順は、明示的な同期がなければ通常保証されません。「startした順＝終了する順」ではありません。

Object Oriented · Inheritance

5. 継承を詳しく — extends / super / override

継承は、既存クラスの性質を利用して新しいクラスを作る仕組みです。継承される側をスーパークラス（親クラス）、継承する側をサブクラス（子クラス）と呼びます。Javaの継承問題では「何を引き継げるか」「どのメソッドが呼ばれるか」「どのコンストラクタが先に動くか」「変数の型と実体の型が何か」を分けて考えるのが重要です。

1. まず基本形

class → class は extends
class Animal {
    String name;

    void speak() {
        System.out.println("sound");
    }
}

class Cat extends Animal {
    void meow() {
        System.out.println("meow");
    }
}

Cat は Animal のサブクラスです。Cat のオブジェクトは、自分で定義した meow() に加えて、継承した name や speak() を利用できます。

is-a 関係: Cat extends Animal は「Cat は Animal の一種」と考えます。継承は単なるコードコピーではなく、型の親子関係も作ります。

2. extends / implements の使い分け

左側右側キーワード例
classclassextendsclass Cat extends Animal
classinterfaceimplementsclass Cat implements Runner
interfaceinterfaceextendsinterface FastRunner extends Runner
頻出: class が interface を使うときは implements。interface 同士は extends です。

3. Javaのclassは多重継承できない

これは不可
class C extends A, B {  // コンパイルエラー
}

1つのclassが直接 extends できるclassは1つだけです。一方で、interfaceは複数実装できます。

interfaceは複数implements可能
class Robot implements Runnable, AutoCloseable {
    public void run() {}
    public void close() {}
}

4. 何が継承される？

メンバサブクラスから扱える？注意点
public○どこからでもアクセス可能
protected○サブクラスから利用できる。別パッケージでは参照方法に制約あり
package-private同一パッケージなら○別パッケージのサブクラスからはアクセス不可
private直接は×privateメンバはサブクラスに継承されず、名前で直接アクセスできない
コンストラクタ×コンストラクタは継承されない。super(...) で呼び出す
privateに注意: 親クラスのprivateフィールドがオブジェクト内に存在していても、子クラスのコードから this.privateField のように直接触ることはできません。必要なら親側のpublic/protectedメソッドを通します。

5. コンストラクタは継承されない

メソッドやフィールドとは違い、コンストラクタそのものはサブクラスへ継承されません。サブクラスは自分自身のコンストラクタを持ち、その開始時にスーパークラスのコンストラクタを呼びます。

super(...)
class Animal {
    String name;

    Animal(String name) {
        this.name = name;
    }
}

class Cat extends Animal {
    Cat(String name) {
        super(name);
    }
}

super(name) は Animal(String name) を呼びます。Java 17では明示的な super(...) / this(...) はコンストラクタ本体の先頭に置きます。

6. super() は省略されることがある

暗黙の super()
class Parent {
    Parent() {
        System.out.println("Parent");
    }
}

class Child extends Parent {
    Child() {
        // 先頭に super(); が暗黙に入る
        System.out.println("Child");
    }
}

この場合の出力順は Parent → Child です。子の初期化より前に親のコンストラクタが実行されます。

コンパイルエラーの定番: 親に引数付きコンストラクタしかなく、子のコンストラクタで適切な super(引数) を書かなければ、暗黙の super() が成立せずコンパイルエラーです。

7. this(...) と super(...) はどちらか一方

同じコンストラクタから別の自クラスコンストラクタを呼ぶなら this(...)、親コンストラクタを直接呼ぶなら super(...) を使います。どちらも先頭のコンストラクタ呼出しになるため、同じコンストラクタで両方を直接書くことはできません。

this(...) から最終的に super(...)
class Cat extends Animal {
    Cat() {
        this("no-name");
    }

    Cat(String name) {
        super(name);
    }
}

8. オーバーライドとは

サブクラスが、親から継承したインスタンスメソッドと同じシグネチャのメソッドを定義して動作を差し替えることをオーバーライドと呼びます。

@Override
class Animal {
    void speak() {
        System.out.println("animal");
    }
}

class Cat extends Animal {
    @Override
    void speak() {
        System.out.println("cat");
    }
}

@Override は必須ではありませんが、スペルミスや引数違いで「実はオーバーライドできていない」問題をコンパイラに検出してもらえるため、基本的に付けます。

9. オーバーロードとオーバーライドを混同しない

オーバーライドオーバーロード
目的親の動作を差し替える同名メソッドを引数違いで増やす
引数同じ異なる必要がある
継承継承関係が前提同一クラス内でも可能
呼出し決定実体の型が重要コンパイル時の引数型が重要

10. オーバーライドのアクセス修飾子

オーバーライド後のメソッドは、親よりアクセス範囲を狭くできません。

public → protected は不可
class Parent {
    public void work() {}
}

class Child extends Parent {
    // protected void work() {} // コンパイルエラー
    public void work() {}       // OK
}

逆に、protected を public に広げることはできます。

11. finalメソッドはオーバーライドできない

final method
class Parent {
    final void fixed() {}
}

class Child extends Parent {
    // void fixed() {} // コンパイルエラー
}

final class はクラス自体の継承を禁止し、final method はそのメソッドのオーバーライドを禁止します。

12. staticメソッドはオーバーライドではなく隠蔽

static メソッドはインスタンスではなくクラスに属するため、子クラスで同じシグネチャを宣言してもインスタンスメソッドのオーバーライドとは扱われません。これはメソッド隠蔽（hiding）です。

static method hiding
class Parent {
    static void show() { System.out.println("Parent"); }
}

class Child extends Parent {
    static void show() { System.out.println("Child"); }
}

Parent p = new Child();
p.show(); // Parent
違い: インスタンスメソッドは実体の型に応じて動的に選ばれますが、staticメソッドは変数・式の型を基に選ばれます。

13. フィールドもオーバーライドされない

子クラスが親と同名のフィールドを宣言すると、フィールドは隠蔽されます。メソッドのような動的ディスパッチは起きません。

field hiding
class Parent {
    String label = "P";
}

class Child extends Parent {
    String label = "C";
}

Parent x = new Child();
System.out.println(x.label); // P

フィールド参照は参照変数の型で決まるため、上の x.label は親側です。

14. 動的ディスパッチ：変数の型と実体の型を分ける

Parent型変数にChildを入れる
class Parent {
    void hello() { System.out.println("Parent"); }
}

class Child extends Parent {
    @Override
    void hello() { System.out.println("Child"); }
    void childOnly() {}
}

Parent p = new Child();
p.hello();       // Child
// p.childOnly(); // コンパイルエラー

p の宣言型は Parent、実際に入っているオブジェクトの実体型は Child です。呼べるメソッド候補は宣言型で決まり、オーバーライドされたメソッドの実装は実体型で決まります。

超重要: 「何を呼べるか＝左辺の型」「オーバーライド後のどの処理が動くか＝実体の型」と分けると解きやすくなります。

15. アップキャスト

Child → Parent
Child child = new Child();
Parent parent = child; // 明示的キャスト不要

子クラスは親クラスの一種なので、サブクラス型からスーパークラス型への変換（アップキャスト）は暗黙にできます。

16. ダウンキャスト

親型の参照を子型へ戻すときは明示的キャストが必要です。ただし、実体がその子型でない場合は実行時に ClassCastException が発生します。

downcast
Parent p = new Child();
Child c = (Child) p; // OK

Parent other = new Parent();
// Child bad = (Child) other; // 実行時 ClassCastException

17. instanceof で安全に型を確認

instanceof
if (p instanceof Child) {
    Child c = (Child) p;
    c.childOnly();
}

instanceof は、その参照先オブジェクトが指定型として扱えるかを確認します。継承やinterface実装も考慮されます。

18. super.method() で親の実装を呼ぶ

super method
class Child extends Parent {
    @Override
    void hello() {
        super.hello();
        System.out.println("Child");
    }
}

オーバーライド後でも super.hello() と書けば親クラス側の実装を明示的に呼べます。

19. super.field で親の同名フィールドを指定

this と super
class Parent {
    int value = 10;
}

class Child extends Parent {
    int value = 20;

    void print() {
        System.out.println(this.value);  // 20
        System.out.println(super.value); // 10
    }
}

this は現在のオブジェクトの子クラス側メンバ、super は直接の親クラス側メンバを明示するために使えます。

20. abstract class と継承

abstract
abstract class Shape {
    abstract double area();

    void printType() {
        System.out.println("shape");
    }
}

class Circle extends Shape {
    double radius;

    Circle(double radius) {
        this.radius = radius;
    }

    @Override
    double area() {
        return Math.PI * radius * radius;
    }
}

抽象クラスはインスタンス化できませんが、通常メソッドやフィールド、コンストラクタを持てます。抽象メソッドを継承した具象クラスは、その抽象メソッドを実装する必要があります。

21. abstract classのコンストラクタも呼ばれる

abstract classは直接 new できませんが、コンストラクタは持てます。具象サブクラスを生成するとき、その初期化の一部としてabstractな親クラスのコンストラクタも実行されます。

22. interface実装はサブクラスにも引き継がれる

間接的なimplements
interface Runner {
    void run();
}

class Animal implements Runner {
    public void run() {
        System.out.println("run");
    }
}

class Cat extends Animal {
}

Runner r = new Cat(); // OK

Cat 自身に implements Runner と書いていなくても、親の Animal が実装しているため Cat も Runner として扱えます。

23. interfaceメソッド実装ではpublicが必要

interface method
interface Runner {
    void run(); // 暗黙に public abstract
}

class Cat implements Runner {
    public void run() { // public が必要
    }
}

interfaceの通常の抽象メソッドは暗黙に public abstract です。実装側でアクセス範囲を狭めることはできないため、public が必要です。

24. Object はclass階層の頂点

明示的に別の親クラスを指定しないclassは、最終的に java.lang.Object を継承しています。そのため toString()、equals()、hashCode() などObject由来のメソッドを利用できます。

暗黙の Object 継承
class User {
    // 実質的には class User extends Object
}

25. instanceof と null

null instanceof
Parent p = null;
System.out.println(p instanceof Parent); // false

null instanceof 型 は例外ではなく false です。型判定問題で出やすいポイントです。

26. 継承チェーンを追う

3段階の継承
class A {}
class B extends A {}
class C extends B {}

C c = new C();
System.out.println(c instanceof C); // true
System.out.println(c instanceof B); // true
System.out.println(c instanceof A); // true
System.out.println(c instanceof Object); // true

サブクラスは直接の親だけでなく、祖先クラスの型としても扱えます。

27. オーバーライドと例外

オーバーライドするメソッドは、親メソッドより広い範囲のchecked例外を新しく投げる宣言にはできません。実務では細かな規則がありますが、初心者段階では「子側が親より危険な契約へ勝手に広げられない」と押さえてください。

28. 戻り値の共変

オーバーライドでは、参照型の戻り値を親より具体的なサブタイプへ狭められる場合があります。

covariant return
class AnimalFactory {
    Animal create() { return new Animal(); }
}

class CatFactory extends AnimalFactory {
    @Override
    Cat create() { return new Cat(); }
}

29. 継承よりコンポジションが適する場合もある

「AはBの一種（is-a）」なら継承が自然ですが、「AはBを持っている（has-a）」だけなら、フィールドとして別オブジェクトを持つコンポジションの方が適切なことがあります。

has-a
class Engine {}

class Car {
    private final Engine engine = new Engine();
}

Car extends Engine は意味的に不自然ですが、Car が Engine を持つのは自然です。

30. 問題を解くときの順番

クラス図を頭の中で作る — 誰が誰をextends / implementsしているか整理する。
コンストラクタを追う — this(...) → super(...) → 親の初期化順を見る。
左辺の宣言型を見る — その変数からコンパイル上何を呼べるか決める。
右辺の実体型を見る — オーバーライドされたインスタンスメソッドの実行先を決める。
static / fieldを別扱いにする — 動的ディスパッチされない。
キャストの向きを確認する — upcastは暗黙、downcastは明示＋実体型確認。

検定での典型的な引っかけ一覧

記述判定理由
class → interface は extends×implements
interface → interface は implements×extends
classは2つのclassを直接継承できる×classの直接の親は1つ
コンストラクタは子へ継承される×継承されず、super(...) で呼ぶ
子→親への代入にはキャストが必要×アップキャストは暗黙
親→子への代入は常に安全×実体型が違うとClassCastException
オーバーライドされたメソッドは実体型で選ばれる○動的ディスパッチ
同名フィールドも実体型で選ばれる×フィールドは参照型で決まる
staticメソッドは通常のオーバーライド×メソッド隠蔽
final classは継承できる×継承禁止
final methodは子で上書きできる×オーバーライド禁止
abstract classはコンストラクタを持てない×持てる
abstract classは直接newできる×インスタンス化不可

最終整理: 継承問題は「継承関係」「アクセス可能性」「コンストラクタ連鎖」「宣言型」「実体型」「instance/static/fieldの違い」の6項目に分けて読むと、長いコードでも追いやすくなります。

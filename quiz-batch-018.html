interface / default / multiple inheritance

Q356. 出力は？

interface Left {
    default String id() { return "L"; }
}
interface Right {
    default String id() { return "R"; }
}
interface Both extends Left, Right {
    @Override
    default String id() {
        return Left.super.id() + Right.super.id();
    }
}
class Impl implements Both { }

System.out.println(new Impl().id());
A. LR
B. L
C. コンパイルエラー
答え・解説
A。LR。2つの親interfaceから同名defaultメソッドを継ぐ場合、Both側で競合を解消できます。直接の親interfaceはLeft.super、Right.superで明示して呼び分けられます。
interface / static / compile error

Q357. コンパイルできる？

interface Converter {
    static int doubleOf(int n) { return n * 2; }
}
class FastConverter implements Converter { }

System.out.println(FastConverter.doubleOf(4));
A. できて、8と表示される
B. できない
C. コンパイルできるが実行時例外
答え・解説
B。interfaceのstaticメソッドは実装クラスへ継承されません。Converter.doubleOf(4)のように、宣言したinterface名で呼び出します。
inheritance / private / modifiers

Q358. 出力は？

class Parent {
    private int code() { return 1; }
}
class Child extends Parent {
    String code() { return "C"; }
}

System.out.println(new Child().code());
A. C
B. 1
C. 戻り値型が異なるためコンパイルエラー
答え・解説
A。C。ParentのprivateメソッドはChildへ継承されないため、Childのcode()はオーバーライドではなく別の宣言です。したがって戻り値型が異なっていても競合しません。
constructor / this / compile error

Q359. コンパイルできる？

class Box {
    int size = 5;

    Box() {
        this(size);
    }
    Box(int n) { }
}
A. できる
B. できない
答え・解説
B。できません。明示的なthis(...)の引数評価では、supertypeのコンストラクタ呼び出しが完了する前にインスタンスフィールドsizeを参照できません。
constructor / super / chaining

Q360. 出力は？

class A {
    A() { System.out.print("A"); }
}
class B extends A {
    B() {
        this(2);
        System.out.print("B");
    }
    B(int n) {
        System.out.print(n);
    }
}

new B();
A. A2B
B. 2AB
C. AAB2
答え・解説
A。A2B。B()はthis(2)へ委譲し、B(int)の先頭には暗黙のsuper()があります。Aのコンストラクタ→B(int)本体→B()本体の順です。
static / null reference

Q361. 実行結果は？

class Flag {
    static int value = 7;
}

Flag f = null;
System.out.println(f.value);
A. 7
B. NullPointerException
C. コンパイルエラー
答え・解説
A。7。staticフィールドは参照先オブジェクトではなく型に属します。f.valueという書き方自体は推奨されませんが、ここではインスタンスを参照しないためnullでも例外になりません。
Map / computeIfPresent / null

Q362. 出力は？

Map<String,Integer> m = new HashMap<>();
m.put("a", 1);
m.put("b", 2);

m.computeIfPresent("a", (k, v) -> null);
m.computeIfPresent("c", (k, v) -> 99);

System.out.println(m.containsKey("a") + ":" + m.size());
A. true:2
B. false:1
C. false:2
答え・解説
B。false:1。既存キーaに対するcomputeIfPresentの結果がnullなので、そのmappingは削除されます。存在しないcには処理が適用されません。
Map / replace / conditional update

Q363. 出力は？

Map<String,Integer> m = new HashMap<>();
m.put("x", 1);

boolean a = m.replace("x", 2, 3);
boolean b = m.replace("x", 1, 4);

System.out.println(a + ":" + b + ":" + m.get("x"));
A. false:true:4
B. true:true:4
C. false:false:1
答え・解説
A。false:true:4。3引数のreplace(key, oldValue, newValue)は現在値がoldValueと一致したときだけ置換します。最初は不一致、2回目は一致します。
Collections / unmodifiable view

Q364. 出力は？

List<String> base =
    new ArrayList<>(Arrays.asList("A", "B"));
List<String> view = Collections.unmodifiableList(base);

base.set(1, "X");
System.out.println(view);
A. [A, B]
B. [A, X]
C. UnsupportedOperationException
答え・解説
B。[A, X]。unmodifiableListは元Listの読み取り専用ビューです。view経由の変更は禁止されますが、元のbaseを変更するとviewから見える内容にも反映されます。
Set / LinkedHashSet / order

Q365. 出力は？

Set<String> s = new LinkedHashSet<>(
    Arrays.asList("A", "B", "C")
);

s.remove("B");
s.add("B");

System.out.println(s);
A. [A, B, C]
B. [A, C, B]
C. [B, A, C]
答え・解説
B。[A, C, B]。LinkedHashSetは挿入順を保持します。一度Bを削除してから再追加すると、その新しい挿入位置は末尾になります。
array / Arrays.copyOf / independence

Q366. 出力は？

int[] a = {1, 2};
int[] b = Arrays.copyOf(a, 4);

b[0] = 9;
System.out.println(
    Arrays.toString(a) + ":" + Arrays.toString(b)
);
A. [1, 2]:[9, 2, 0, 0]
B. [9, 2]:[9, 2, 0, 0]
C. [1, 2]:[9, 2, null, null]
答え・解説
A。Arrays.copyOfは別の配列を作ります。長くしたint配列の追加部分は既定値0で埋められ、bの要素を変更してもaには影響しません。
loop / labeled break / trace

Q367. 出力は？

int n = 0;
outer:
for (int i = 0; i < 3; i++) {
    for (int j = 0; j < 3; j++) {
        if (i + j == 3) break outer;
        n++;
    }
}

System.out.println(n);
A. 4
B. 5
C. 6
答え・解説
B。5。i=0では3回、i=1ではj=0,1の2回だけn++されます。i=1,j=2で条件が成立し、ラベル付きbreakで外側のforも終了します。
enhanced for / references / array

Q368. 出力は？

StringBuilder[] a = {
    new StringBuilder("A"),
    new StringBuilder("B")
};

for (StringBuilder s : a) {
    s.append("!");
    s = new StringBuilder("X");
}

System.out.println(a[0] + ":" + a[1]);
A. A:B
B. A!:B!
C. X:X
答え・解説
B。A!:B!。拡張forの変数sは各配列要素の参照を受け取るローカル変数です。参照先へのappendは配列要素にも見えますが、s自体を別オブジェクトへ再代入しても配列の参照は置き換わりません。

Object x = new StringBuilder("A");

boolean / | / side effect

Q371. 出力は？

int n = 0;
boolean result = true | (++n > 0);

System.out.println(result + ":" + n);

instanceof / compile error / final types

Q372. コンパイルできる？

String s = "java";

A. できてfalseと表示される
B. できてtrueと表示される

Thread / synchronized / locks

Q373. 正しい説明は？

class Gate {
    synchronized void enter() { }
    static synchronized void reset() { }
}
A. enter()とreset()は常に同じロックを使う
B. enter()は対象インスタンス、reset()はGate.classをロックする
C. どちらもGate.classをロックする
答え・解説
B。通常のsynchronizedインスタンスメソッドはthis、static synchronizedメソッドはそのClassオブジェクトをロックします。ロック対象は別物です。
Thread / sleep / current thread

Q374. t.sleep(100)で休止するのは？

public static void main(String[] args) throws Exception {
    Thread t = new Thread(() -> { });
    t.start();
    t.sleep(100);
}
A. 必ずt
B. sleepを呼び出している現在のスレッド（ここではmain）
C. tとmainの両方
答え・解説
B。sleepはstaticメソッドで、「現在実行中のスレッド」を休止します。インスタンスt経由で呼ぶ書き方は可能ですが、t自身を指定して眠らせる意味にはなりません。
Thread / join / trace

Q375. 出力は？

public static void main(String[] args) throws Exception {
    Thread t = new Thread(() -> System.out.print("T"));
    t.start();
    t.join();
    t.join();
    System.out.print("M");
}
A. TM
B. TTM
C. MT
答え・解説
A。TM。最初のjoin()でtの終了を待つためTが先に出ます。終了済みThreadにもう一度join()してもrun()は再実行されず、待機せず戻ります。

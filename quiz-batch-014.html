interface / default / inheritance

Q276. 出力は？

interface Root {
    default String mark() { return "R"; }
}
interface Branch extends Root {
    default String mark() { return "B"; }
}
class Leaf implements Root, Branch { }

System.out.println(new Leaf().mark());
A. R
B. B
C. コンパイルエラー
答え・解説
B。B。BranchはRootを継承した、より具体的なinterfaceです。両方が同じdefaultメソッドを持つ場合でも、継承関係があればより具体的なBranch側の実装が選ばれます。
inheritance / override / modifiers / compile error

Q277. Childはコンパイルできる？

class Parent {
    public void run() { }
}
class Child extends Parent {
    @Override
    protected void run() { }
}
A. できる
B. できない
答え・解説
B。オーバーライドでは親メソッドよりアクセス範囲を狭くできません。Parent.run()はpublicなので、Child.run()もpublicである必要があります。
inheritance / overload / override / trace

Q278. 出力は？

class Parent {
    void show(Object x) { System.out.print("PO"); }
}
class Child extends Parent {
    @Override
    void show(Object x) { System.out.print("CO"); }
    void show(String x) { System.out.print("CS"); }
}

Parent p = new Child();
p.show("java");
A. PO
B. CO
C. CS
答え・解説
B。CO。まず宣言型Parentを基準にオーバーロード解決され、show(Object)が選ばれます。その後、実体がChildなのでオーバーライドされたChild.show(Object)が実行されます。
constructor / this / initializer / trace

Q279. 出力は？

class Box {
    { System.out.print("I"); }

    Box() {
        this(2);
        System.out.print("A");
    }
    Box(int n) {
        System.out.print(n);
    }
}

new Box();
A. I2A
B. 2IA
C. IIA2
答え・解説
A。I2A。同一オブジェクトの生成でインスタンス初期化子は1回だけ実行されます。this(2)で到達したコンストラクタ本体より前にIが出力され、その後2、最後に元のBox()へ戻ってAが出力されます。
constructor / this / compile error

Q280. 次のクラスはコンパイルできる？

class LoopCtor {
    LoopCtor() {
        this(1);
    }
    LoopCtor(int n) {
        this();
    }
}
A. できる
B. できない
答え・解説
B。2つのコンストラクタがthis(...)で互いを呼び続けるため、再帰的なコンストラクタ呼び出しになります。コンパイラが検出してエラーにします。
static / inheritance / initialization order

Q281. 出力は？

class Parent {
    static { System.out.print("P"); }
    Parent() { System.out.print("p"); }
}
class Child extends Parent {
    static { System.out.print("C"); }
    Child() { System.out.print("c"); }
}

new Child();
new Child();
A. PCpcpc
B. PpCcPpCc
C. PCPCpcpc
答え・解説
A。PCpcpc。クラス初期化は最初の利用時に親P→子Cの順で1回だけ実行されます。各newではParentコンストラクタp→Childコンストラクタcが実行されるため、pcが2回続きます。
Map / merge

Q282. 出力は？

Map<String,Integer> map = new HashMap<>();
map.put("x", 2);

int a = map.merge("x", 3, Integer::sum);
int b = map.merge("y", 4, Integer::sum);

System.out.println(a + ":" + b + ":" + map.get("x"));
A. 3:4:3
B. 5:4:5
C. 5:7:5
答え・解説
B。5:4:5。xには既存値2があるのでmergeは2と3を合計して5に更新します。yは未登録なので4がそのまま登録されます。
Map / values / view

Q283. 出力は？

Map<String,Integer> map = new LinkedHashMap<>();
map.put("a", 1);
map.put("b", 2);
map.put("c", 3);

Collection<Integer> values = map.values();
values.remove(2);

System.out.println(map);
A. {a=1, b=2, c=3}
B. {a=1, c=3}
C. {b=2}
答え・解説
B。{a=1, c=3}。values()はコピーではなくMapに結び付いたビューです。値2をビューから削除すると、その値に対応するbのエントリもMapから削除されます。
HashSet / equals / identity

Q284. 出力は？

class Token {
    int id;
    Token(int id) { this.id = id; }
}

Set<Token> set = new HashSet<>();
set.add(new Token(1));
set.add(new Token(1));

System.out.println(set.size());
A. 1
B. 2
C. コンパイルエラー
答え・解説
B。2。Tokenはequals()とhashCode()をオーバーライドしていないため、2つのnew Token(1)は別オブジェクトとして扱われます。フィールドidが同じだけではHashSet上の重複にはなりません。
TreeSet / natural order / String

Q285. 出力は？

Set<String> set = new TreeSet<>();
set.add("10");
set.add("2");
set.add("1");

System.out.println(set);
A. [1, 2, 10]
B. [1, 10, 2]
C. [10, 2, 1]
答え・解説
B。[1, 10, 2]。Stringの自然順序は数値としてではなく文字列の辞書順で比較されます。そのため先頭文字が同じ1と10が2より前に並びます。
array / 2D / shallow clone

Q286. 出力は？

int[][] a = { {1, 2}, {3} };
int[][] b = a.clone();

b[0][0] = 9;

System.out.println(
    a[0][0] + ":" + (a == b) + ":" + (a[0] == b[0])
);
A. 1:false:false
B. 9:false:true
C. 9:true:true
答え・解説
B。9:false:true。2次元配列のclone()で複製されるのは外側の配列です。内側のint[]参照は共有されるためa[0]とb[0]は同じ配列を指し、要素変更が両方から見えます。
for / multiple variables / trace

Q287. 出力は？

int sum = 0;

for (int i = 0, j = 4; i < j; i++, j--) {
    sum += i + j;
}

System.out.println(sum);
A. 4
B. 8
C. 12
答え・解説
B。8。反復は(i,j)=(0,4)と(1,3)の2回です。それぞれ4を加え、更新後に(2,2)となると条件i < jがfalseになって終了します。
do-while / continue / trace

Q288. 出力は？

int i = 0;
int sum = 0;

do {
    i++;
    if (i % 2 == 0) {
        continue;
    }
    sum += i;
} while (i < 4);

System.out.println(sum);
A. 4
B. 6
C. 10
答え・解説
A。4。i=1と3だけが加算されます。do-whileでcontinueすると本体の残りを飛ばした後にwhile条件を評価して次の反復へ進むため、偶数2と4は加算されません。
instanceof / final class / compile error

Q289. 次のコードはどうなる？

String s = "java";
System.out.println(s instanceof Runnable);
A. falseと表示
B. trueと表示
C. コンパイルエラー
答え・解説
C。StringはfinalクラスでRunnableを実装していません。StringのサブクラスがRunnableを実装する可能性もないため、このinstanceofは型の関係が成立し得ずコンパイルエラーになります。
boolean / precedence / short-circuit

Q290. 出力は？

int n = 0;

boolean result =
    (++n > 0) || (++n > 1) && (++n > 2);

System.out.println(n + ":" + result);
A. 1:true
B. 2:true
C. 3:true
答え・解説
A。1:true。式は左側の条件がtrueになった時点で||が短絡評価するため、右側の&&全体は評価されません。したがってnは最初の++だけで1です。
cast / runtime error

Q291. 次のコードはどうなる？

Number n = Double.valueOf(2.5);
Integer x = (Integer) n;

System.out.println(x);
A. 2と表示
B. コンパイルエラー
C. 実行時にClassCastException
答え・解説
C。Number型の参照はIntegerへ明示的にキャストできるためコンパイルは通ります。しかし実体はDoubleなので、実行時の型検査でClassCastExceptionになります。
Thread / start / runtime error

Q292. 次のコードはどうなる？

public static void main(String[] args) throws Exception {
    Thread t = new Thread(() -> { });

    t.start();
    t.join();
    t.start();
}
A. 正常終了する
B. 2回目のstart()でIllegalThreadStateException
C. 2回目は新しいThreadとして開始する
答え・解説
B。同じThreadオブジェクトにstart()を呼べるのは1回だけです。終了後であっても再startはできず、2回目の呼び出しでIllegalThreadStateExceptionが発生します。
Thread / join / order

Q293. 出力順として確定するものは？

public static void main(String[] args) throws Exception {
    Thread t = new Thread(
        () -> System.out.print("T")
    );

    t.start();
    t.join();
    System.out.print("A");
}
A. TA
B. AT
C. TAまたはAT
答え・解説
A。TA。join()は対象スレッドtが終了するまで現在のスレッドを待機させます。tがTを出力して終了した後で、mainスレッドがAを出力します。
Thread / isAlive / lifecycle

Q294. 出力は？

public static void main(String[] args) throws Exception {
    Thread t = new Thread(() -> { });

    System.out.print(t.isAlive() + ":");
    t.start();
    t.join();
    System.out.println(t.isAlive());
}
A. false:false
B. false:true
C. true:false
答え・解説
A。false:false。start()前のThreadはまだ生存していません。またjoin()が戻った時点ではtのrun()は終了済みなので、後半のisAlive()もfalseです。
Thread / yield / scheduling

Q295. 正しい説明は？

Thread.yield();
System.out.println("A");
A. yield()を呼ぶと現在のThreadは終了する
B. 他のThreadが必ず1回実行されてからAが表示される
C. 実行機会を譲るヒントにはなるが、切り替わる保証はなく、その後Aは実行される
答え・解説
C。yield()はスケジューラへ実行機会を譲る意思を示す静的メソッドですが、別Threadへ必ず切り替わる保証はありません。現在のThreadは終了せず、その後のprintlnも続けて実行されます。

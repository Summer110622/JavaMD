Java Concurrency

スレッドと並行処理を、仕組みから理解する。

Threadの生成だけでなく、競合・可視性・排他制御・スレッドプール・非同期処理・Virtual Threadまでを、役割の違いが分かるように整理します。

1. スレッドとは

プロセスは実行中のプログラム単位、スレッドはその中で命令列を実行する単位です。同一プロセス内のスレッドはヒープなどを共有するため、同じオブジェクトへ同時アクセスできます。

Concurrency
複数の処理が時間的に重なって進むこと。
Parallelism
複数CPUコアなどで実際に同時実行すること。
Javaでは「共有された可変状態」が並行処理の主要な難所です。共有を減らし、不変データやメッセージ受け渡しを優先すると設計しやすくなります。

2. Thread / Runnable

Runnable + Thread
Runnable task = () -> {
    System.out.println(Thread.currentThread().getName());
};

Thread thread = new Thread(task, "worker-1");
thread.start();
start() と run() は別物: start() は新しいスレッドを開始し、そのスレッド上で run() を呼びます。run() を直接呼ぶだけでは現在のスレッド上で普通のメソッドとして実行されます。
join
Thread t = new Thread(() -> doWork());
t.start();
t.join(); // tの終了を待つ
System.out.println("done");

4. Race Condition

count++ は1操作に見えても、読み取り→加算→書き戻しの複数操作です。複数スレッドが同時に行うと更新が失われる可能性があります。

危険な例
class Counter {
    private int count = 0;
    void increment() { count++; }
    int get() { return count; }
}

この問題には少なくとも atomicity（不可分性） と visibility（可視性） の2軸があります。

5. synchronized

synchronized はmonitor lockを使い、同一ロックを使うクリティカルセクションを同時に1スレッドだけ実行させます。排他に加えて、ロック解放・取得間の可視性も保証します。

synchronized method
class Counter {
    private int count;

    synchronized void increment() {
        count++;
    }

    synchronized int get() {
        return count;
    }
}
synchronized block
private final Object lock = new Object();

void update() {
    synchronized (lock) {
        // critical section
    }
}

6. volatile

volatile は主に可視性と一定のorderingを保証しますが、複合操作を原子的にはしません。

停止フラグ
class Worker {
    private volatile boolean running = true;

    void stop() { running = false; }

    void runLoop() {
        while (running) {
            doWork();
        }
    }
}
volatile int count; にしても count++ はatomicになりません。単純カウンタなら AtomicInteger を検討します。

8. wait / notify / notifyAll

wait() はmonitorを解放して待機し、notify()/notifyAll() は同じmonitorで待つスレッドを起こします。必ず対応する synchronized 内で使います。

条件待ち
synchronized (lock) {
    while (!ready) {
        lock.wait();
    }
    consume();
}

synchronized (lock) {
    ready = true;
    lock.notifyAll();
}
実務では低レベルな wait/notify より、BlockingQueue、CountDownLatch、Semaphore、CompletableFuture など高水準APIを優先する場面が多いです。

9. ExecutorService

タスクとスレッド管理を分離します。アプリケーションコードで大量の new Thread(...) を直接管理するより、Executorを使う方が一般的です。

Fixed Thread Pool
try (ExecutorService executor = Executors.newFixedThreadPool(4)) {
    executor.submit(() -> processA());
    executor.submit(() -> processB());
}
API意味
execute(Runnable)戻り値なしタスクを投入
submit(...)Futureを返す
shutdown()新規受付停止、既存タスクは継続
shutdownNow()割り込みを試みて停止要求

10. Future / CompletableFuture

Future
Future<Integer> future = executor.submit(() -> 40 + 2);
Integer result = future.get(); // 完了までblock
CompletableFuture
CompletableFuture<String> future =
    CompletableFuture.supplyAsync(() -> loadUser())
        .thenApply(User::name)
        .thenApply(String::toUpperCase)
        .exceptionally(ex -> "UNKNOWN");

String name = future.join();

thenCompose は非同期処理を直列合成、thenCombine は独立した2処理の結果を結合するときに使います。

12. Virtual Threads

Java 21で正式導入されたVirtual Threadは、JVMが管理する軽量スレッドです。大量のI/O待ちタスクを「1タスク1スレッド」に近い直感的なスタイルで扱いやすくします。

Virtual Thread
Thread.startVirtualThread(() -> {
    String body = fetchFromNetwork();
    System.out.println(body);
});
Virtual Thread Executor
try (ExecutorService executor =
         Executors.newVirtualThreadPerTaskExecutor()) {

    Future<String> a = executor.submit(() -> loadA());
    Future<String> b = executor.submit(() -> loadB());

    System.out.println(a.get() + b.get());
}
Virtual ThreadはCPU処理を魔法のように高速化する仕組みではありません。特にI/O待ちが多い大量タスクで有効です。CPU-bound処理はCPUコア数という物理的制約を受けます。

13. interrupt とキャンセル

Javaのinterruptは強制終了ではなく「中断要求」です。対象コードは割り込みを検知して協調的に終了します。

InterruptedException
try {
    Thread.sleep(1000);
} catch (InterruptedException e) {
    Thread.currentThread().interrupt();
    return;
}
catchした後に処理継続する場合でも、上位へ中断状態を伝える必要があるなら Thread.currentThread().interrupt() でinterrupt flagを復元します。

14. Deadlock

複数スレッドが互いのロック解放を永久に待つ状態です。

典型構造
// Thread A: lock1 → lock2
// Thread B: lock2 → lock1
// 両方が最初のlockを取ると互いに次を待つ

対策はロック取得順序を統一する、ロック粒度を減らす、共有状態を減らす、必要なら tryLock を使う、などです。

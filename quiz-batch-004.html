interface / abstract

Q76. 次のコードはコンパイルできる？

interface Reader { void read(); }
abstract class BaseReader implements Reader { }
class TextReader extends BaseReader {
    public void read() { System.out.print("text"); }
}
A. できる
B. BaseReaderがread()を実装していないのでできない
C. TextReaderはReaderを直接implementsしていないのでできない
答え・解説
A。 抽象クラスはinterfaceの抽象メソッドを未実装のまま残せます。最終的な具象クラスTextReaderがpublicでread()を実装しているため有効です。
override / access

Q77. 次のオーバーライドは有効？

class Parent {
    protected Number value() { return 1; }
}
class Child extends Parent {
    public Integer value() { return 2; }
}
A. 有効
B. 戻り値型が違うので無効
C. protectedをpublicに広げているので無効
答え・解説
A。 オーバーライドではアクセス範囲を広げられ、戻り値は共変戻り値としてサブタイプへ狭められます。IntegerはNumberのサブクラスです。
final / inheritance

Q78. 次のコードはどうなる？

final class Token { }
class SpecialToken extends Token { }
A. 正常にコンパイル
B. コンパイルエラー
C. 実行時例外
答え・解説
B。 finalクラスは継承できません。finalメソッドがオーバーライド不可なのと同じく、継承階層をそこで止めます。
constructor / super

Q79. 次のChildはコンパイルできる？

class Parent {
    Parent(int n) { }
}
class Child extends Parent {
    Child() { }
}
A. できる
B. できない
答え・解説
B。 Child()には暗黙のsuper()が挿入されますが、Parentには引数なしコンストラクタがありません。Child側でsuper(値)を明示する必要があります。
this / constructor chain

Q80. 出力は？

class Box {
    int n;
    Box() { this(4); System.out.print("A"); }
    Box(int n) { this.n = n; System.out.print("B"); }
}
Box b = new Box();
System.out.println(b.n);
A. AB4
B. BA4
C. B4A
答え・解説
B。BA4。 Box()は最初にthis(4)で別コンストラクタを実行するためB、その後A、最後にフィールドnの4が表示されます。
static / initialization

Q81. 出力は？

class Counter {
    static int total = 1;
    int id = total++;
}
Counter a = new Counter();
Counter b = new Counter();
System.out.println(a.id + ":" + b.id + ":" + Counter.total);
A. 1:1:1
B. 1:2:3
C. 2:3:3
答え・解説
B。1:2:3。 totalは共有され、各インスタンス初期化時に後置インクリメントされます。idには増加前の値が入ります。
Map / getOrDefault

Q82. 出力は？

Map<String,Integer> m = new HashMap<>();
m.put("x", null);
System.out.println(m.getOrDefault("x", 9));
System.out.println(m.getOrDefault("y", 9));
A. null / 9
B. 9 / 9
C. NullPointerException
答え・解説
A。 getOrDefaultはキーが存在する場合、その対応値を返します。xは存在して値がnullなのでnull、存在しないyだけ既定値9です。
Set / retainAll

Q83. 出力されるsizeは？

Set<Integer> a = new HashSet<>(Arrays.asList(1, 2, 3));
Set<Integer> b = new HashSet<>(Arrays.asList(2, 3, 4));
a.retainAll(b);
System.out.println(a.size());
A. 1
B. 2
C. 4
答え・解説
B。2。 retainAllは共通要素だけを残します。aには2と3が残るので要素数は2です。HashSetの表示順そのものには依存しません。
List / fixed size

Q84. 次のコードはどうなる？

List<String> xs = Arrays.asList("A", "B");
xs.set(0, "X");
xs.add("C");
System.out.println(xs);
A. [X, B, C]
B. addでUnsupportedOperationException
C. setでUnsupportedOperationException
答え・解説
B。 Arrays.asListで得るListは固定長です。要素の置換setは可能ですが、要素数を変えるadd/removeはUnsupportedOperationExceptionになります。
array / reference

Q85. 出力は？

int[] a = {1, 2};
int[] b = a;
b[0] = 9;
System.out.println(a[0] + ":" + (a == b));
A. 1:false
B. 9:true
C. 9:false
答え・解説
B。9:true。 配列変数には参照が入ります。b=aで同じ配列を指すためb経由の変更がaからも見え、参照比較もtrueです。
loop / labeled continue

Q86. countはいくつ？

int count = 0;
outer:
for (int i = 0; i < 3; i++) {
    for (int j = 0; j < 3; j++) {
        if (j == 1) continue outer;
        count++;
    }
}
System.out.println(count);
A. 3
B. 6
C. 9
答え・解説
A。3。 各iでj=0のときだけcount++され、j=1で外側ループの次の反復へ進みます。よって3回です。
array / loop trace

Q87. 出力は？

int[] v = {2, 4, 6, 8};
int x = 0;
for (int i = v.length - 1; i >= 0; i -= 2) {
    x += v[i];
}
System.out.println(x);
A. 8
B. 12
C. 20
答え・解説
B。12。 iは3、1と進むためv[3]=8とv[1]=4を加算します。
instanceof / interface

Q88. 出力は？

interface Mark { }
class Item { }
class Special extends Item implements Mark { }
Item x = new Special();
System.out.println(x instanceof Mark);
A. true
B. false
C. コンパイルエラー
答え・解説
A。 instanceofは実行時の実体を確認します。xの宣言型はItemでも実体SpecialがMarkを実装しているためtrueです。
cast / field vs method

Q89. 出力は？

class A { int n = 1; int get() { return n; } }
class B extends A { int n = 2; int get() { return n; } }
A x = new B();
System.out.println(x.n + ":" + x.get());
A. 1:1
B. 1:2
C. 2:2
答え・解説
B。1:2。 フィールド参照は変数の宣言型Aで決まり、オーバーライドされたインスタンスメソッドは実体Bで決まります。
boolean / & vs &&

Q90. 出力は？

int n = 0;
boolean r = false & (++n > 0);
System.out.println(n + ":" + r);
A. 0:false
B. 1:false
C. 1:true
答え・解説
B。1:false。 booleanの&演算子は両辺を評価します。左辺がfalseでも++nが実行されます。短絡する&&との違いが要点です。
boolean / short circuit

Q91. 出力は？

String s = null;
boolean ok = (s == null) || s.isEmpty();
System.out.println(ok);
A. true
B. false
C. NullPointerException
答え・解説
A。true。 ||は左辺がtrueなら右辺を評価しないため、s.isEmpty()は呼ばれずNullPointerExceptionも発生しません。
Thread / start vs run

Q92. 新しいスレッドを開始しない呼び出しはどれ？

Thread t = new Thread(() -> System.out.print("X"));
A. t.start()
B. t.run()
答え・解説
B。 run()を直接呼ぶと通常のメソッド呼び出しとして現在のスレッドで実行されます。新しいスレッドを開始するのはstart()です。
Thread / synchronized lock

Q93. static synchronizedメソッドがロックする対象として最も適切なのは？

class Store {
    static synchronized void update() { }
}
A. 呼び出したStoreインスタンス
B. Store.classに対応するClassオブジェクト
C. 現在実行中のThreadオブジェクト
答え・解説
B。 static synchronizedメソッドはクラス単位のモニタ、つまりStore.classに対応するClassオブジェクトをロックします。
Thread / interrupt

Q94. 次のcatchが必要になる主な理由は？

try {
    Thread.sleep(100);
} catch (InterruptedException e) {
    System.out.print("interrupted");
}
A. sleepはInterruptedExceptionを送出し得るchecked例外APIだから
B. sleepは必ず例外を投げるから
C. Threadはすべてのメソッドでcatchが必須だから
答え・解説
A。 sleepはInterruptedExceptionを送出し得るため、catchするかthrowsで宣言する必要があります。必ず例外になるわけではありません。
compile error / interface visibility

Q95. 次のコードはコンパイルできる？

interface Job { void run(); }
class Task implements Job {
    void run() { }
}
A. できる
B. できない
答え・解説
B。 interfaceの抽象メソッドは暗黙にpublicです。実装側でアクセス範囲を狭められないため、Task.run()もpublicにする必要があります。

interface / static / inheritance

Q316. 出力は？

interface Audit {
    static String tag() { return "I"; }
}
class Box implements Audit {
    String tag() { return "C"; }
}

System.out.println(new Box().tag() + ":" + Audit.tag());
A. C:I
B. I:I
C. コンパイルエラー
答え・解説
A。C:I。interfaceのstaticメソッドは実装クラスへ継承されません。そのためBoxのtag()は別のインスタンスメソッドとして定義でき、Audit.tag()はinterface名で呼び出します。
interface / default / multiple implements

Q317. 出力は？

interface Left {
    default int value() { return 1; }
}
interface Right {
    default int value() { return 2; }
}
class Both implements Left, Right {
    public int value() {
        return Left.super.value() + Right.super.value();
    }
}

System.out.println(new Both().value());
A. 1
B. 2
C. 3
D. コンパイルエラー
答え・解説
C。3。同じシグネチャのdefaultメソッドを複数interfaceから受ける場合は実装クラス側で解決が必要です。ここではInterfaceName.superの形で両方を明示的に呼び、その合計を返しています。
inheritance / private / method dispatch

Q318. 出力は？

class Base {
    private String mark() { return "B"; }
    String call() { return mark(); }
}
class Sub extends Base {
    public String mark() { return "S"; }
}

System.out.println(new Sub().call());
A. B
B. S
C. コンパイルエラー
答え・解説
A。B。Baseのprivateメソッドmark()はSubへ継承されず、オーバーライドの対象にもなりません。Base.call()内のmark()はBase自身のprivateメソッドを呼びます。
constructor / this / static / final

Q319. 出力は？

class Key {
    static int created = 0;
    final int id;

    Key() { this(++created); }
    Key(int id) { this.id = id; }
}

Key a = new Key();
Key b = new Key();
System.out.println(a.id + ":" + b.id + ":" + Key.created);
A. 1:2:2
B. 1:1:2
C. 2:2:2
答え・解説
A。1:2:2。引数なしコンストラクタはthis(++created)で別コンストラクタへ委譲します。createdは各生成時に1ずつ増え、その値がfinalフィールドidへ一度だけ代入されます。
static / final / class initialization

Q320. 出力は？

class Limits {
    static { System.out.print("I"); }
    static final int MAX = 3;
}

System.out.print(Limits.MAX);
A. I3
B. 3
C. コンパイルエラー
答え・解説
B。3。MAXはプリミティブ型のコンパイル時定数なので参照箇所へ値が埋め込まれます。この参照だけではLimitsのクラス初期化は発生せず、static初期化子Iは実行されません。
constructor / implicit super / compile error

Q321. Childはコンパイルできる？

class Parent {
    Parent(int n) { }
}
class Child extends Parent {
}
A. できる
B. できない
答え・解説
B。できません。Childにはデフォルトコンストラクタが補われますが、その先頭にはsuper()が暗黙挿入されます。Parentには引数なしコンストラクタがないため呼び出せません。
Map / entrySet / view

Q322. 出力は？

Map<String,Integer> map = new HashMap<>();
map.put("a", 1);

Map.Entry<String,Integer> entry =
    map.entrySet().iterator().next();
entry.setValue(7);

Set / retainAll / return value

Q324. 出力は？

Set<String> set = new HashSet<>(
    Arrays.asList("A", "B", "C")
);
boolean changed = set.retainAll(
    Arrays.asList("B", "C", "D")
);

System.out.println(changed + ":" + set.size() + ":" + set.contains("A"));
A. true:2:false
B. false:2:false
C. true:3:true
答え・解説
A。true:2:false。retainAll()は指定Collectionにも含まれる要素だけを残します。Aが削除されるため内容は変化し、戻り値はtrue、残る要素数は2です。

List<Integer> list = new ArrayList<>(

array / 2D array / enhanced for

Q326. 出力は？

int[][] data = {
    {1, 2, 3},
    {},
    {4, 5}
};
int cells = 0;
for (int[] row : data) {
    cells += row.length;
}
System.out.println(data.length + ":" + cells);
A. 3:5
B. 5:3
C. 3:6
答え・解説
A。3:5。data.lengthは行数3です。各行の長さは3、0、2なので、拡張forで合計すると5になります。2次元配列の各行は同じ長さである必要はありません。
for / multiple variables / trace

Q327. 出力は？

int sum = 0;
for (int i = 0, j = 7; i < j; i += 2, j--) {
    sum += i + j;
}
System.out.println(sum);
A. 15
B. 24
C. 30
答え・解説
B。24。ループ本体に入る組は(0,7)、(2,6)、(4,5)で、加算値は7、8、9です。次の(6,4)では条件i < jがfalseになり終了します。
loop / switch / fall-through

Q328. 出力は？

int score = 0;
for (int i = 1; i <= 3; i++) {
    switch (i) {
        case 1: score += 1;
        case 2: score += 2; break;
        default: score += 4;
    }
}
System.out.println(score);
A. 7
B. 9
C. 12
答え・解説
B。9。i=1ではbreakがcase 1にないためcase 2までフォールスルーして3加算します。i=2で2、i=3でdefaultの4を加え、合計9です。

instanceof / compile error / type relation

Q331. 次のコードはコンパイルできる？

String text = "java";

System.out.println(result);
A. でき、falseと表示される

boolean / operator precedence

Q332. 出力は？

boolean result = true | false && false;
System.out.println(result);
A. true
B. false
C. コンパイルエラー
答え・解説
B。false。booleanの|は&&より優先順位が高いため、(true | false) && falseとして評価されます。左側はtrueですが、true && falseなので最終結果はfalseです。
Thread / Runnable / override / run

Q333. 何が表示される？

Thread t = new Thread(
    () -> System.out.print("R")
) {
    @Override
    public void run() {
        System.out.print("M");
    }
};

t.start();
t.join();
A. R
B. M
C. RM
D. MR
答え・解説
B。M。Thread(Runnable)へRunnableを渡していても、この匿名サブクラスはrun()自体をオーバーライドしています。start()後に動くのはオーバーライドされたrun()で、super.run()を呼んでいないためRunnable側のRは実行されません。InterruptedExceptionへの対応は済んでいるものとします。
Thread / Runnable / synchronized / shared lock

Q334. 必ず表示される値は？

class Job implements Runnable {
    int count = 0;
    public synchronized void run() {
        int old = count;
        count = old + 1;
    }
}

Job job = new Job();
Thread t1 = new Thread(job);
Thread t2 = new Thread(job);
t1.start();
t2.start();
t1.join();
t2.join();
System.out.println(job.count);
A. 必ず1
B. 必ず2
C. 1または2
答え・解説
B。必ず2。同じJobインスタンスを2つのThreadが共有し、run()はinstance synchronizedなので同じjobのロックを使います。2回の更新は同時実行されず、join()後には両方が完了しています。InterruptedExceptionへの対応は済んでいるものとします。
Thread / join / checked exception / compile error

Q335. 次のメソッドはコンパイルできる？

void waitFor(Thread t) {
    t.join();
}
A. できる
B. できない
答え・解説
B。できません。join()はInterruptedExceptionを投げる可能性があり、これはチェック例外です。catchするか、waitFor側でthrows InterruptedExceptionを宣言する必要があります。

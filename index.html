Javaソースは通常、javac でバイトコードへ変換され、JVMがそのバイトコードを実行します。OSごとの差をJVMが吸収するため、同じバイトコードを複数環境で実行しやすい設計です。

JDK

4. String・Wrapper・equals

12. 例外処理

例外は正常系とは別の失敗経路を表します。checked例外はコンパイル時に処理が要求され、unchecked例外（RuntimeException 系）は必須ではありません。

try / catch / finally
try {
    int n = Integer.parseInt(input);
} catch (NumberFormatException e) {
    System.err.println("数値ではありません");
} finally {
    System.out.println("必ず実行");
}
try-with-resources
try (var reader = Files.newBufferedReader(path)) {
    System.out.println(reader.readLine());
} catch (IOException e) {
    throw new UncheckedIOException(e);
}
原則: 捕捉して何もしない catch (Exception e) {} は避けます。回復する、意味を付けて再throwする、上位へ伝える、のどれかを明確にします。

15. List — ArrayList / LinkedList / Vector

Listは順序があり、重複を許します。添字アクセスが必要なら基本は ArrayList です。

実装特徴向いている場面
ArrayList可変長配列。getがO(1)ほとんどの通常用途
LinkedList双方向リンク。Dequeも実装両端操作。ただし多くの場面でArrayDequeが優先
Vector古い同期化List新規コードでは通常使わない
ArrayList
List<String> names = new ArrayList<>();
names.add("Alice");
names.add("Bob");
names.add(1, "Carol");

String first = names.get(0);
names.set(0, "Alicia");
names.remove("Bob");
boolean hasCarol = names.contains("Carol");

for (String name : names) {
    System.out.println(name);
}
LinkedList ≠ 常に挿入削除が速い: 挿入位置を探すための走査が必要ならO(n)です。CPUキャッシュ効率も含め、一般用途ではArrayListが有利なことが多いです。

16. Set — HashSet / LinkedHashSet / TreeSet / EnumSet

Setは重複を許しません。「すでに存在するか」を表現したいときに使います。

実装順序性能目安null用途
HashSet保証なし平均O(1)許容高速な重複排除・存在確認
LinkedHashSet挿入順平均O(1)許容順序を維持した重複排除
TreeSetソート順O(log n)通常不可範囲検索・最小最大・整列
EnumSetenum定義順非常に効率的不可enum集合

HashSet

HashSet
Set<String> tags = new HashSet<>();
tags.add("java");
tags.add("stream");
tags.add("java"); // false: 重複なので追加されない

boolean exists = tags.contains("java");
tags.remove("stream");

LinkedHashSet

入力順を保って重複排除
List<String> input = List.of("B", "A", "B", "C");
Set<String> unique = new LinkedHashSet<>(input);
// [B, A, C]

TreeSet

TreeSet は赤黒木ベースの NavigableSet で、自然順序または Comparator に従って常に整列します。

TreeSet / NavigableSet
NavigableSet<Integer> scores = new TreeSet<>();
scores.addAll(List.of(70, 90, 60, 80));

scores.first();      // 60
scores.last();       // 90
scores.lower(80);    // 70  (< 80)
scores.floor(80);    // 80  (<= 80)
scores.higher(80);   // 90  (> 80)
scores.ceiling(75);  // 80  (>= 75)
scores.subSet(70, true, 90, false); // [70, 80]

Setで重要な equals / hashCode

HashSet は hashCode() で候補を絞り、equals() で同一性を判定します。独自クラスを要素にするなら両者の契約が重要です。

契約: a.equals(b) が true なら、a.hashCode() == b.hashCode() でなければなりません。

17. Map — HashMap / LinkedHashMap / TreeMap / EnumMap / ConcurrentHashMap

Mapはキーと値の対応を持ちます。キーは重複できず、同じキーへputすると値が置き換わります。

実装キー順序性能目安代表用途
HashMap保証なし平均O(1)通常の辞書・検索
LinkedHashMap挿入順 / access-order平均O(1)順序保持、LRUの土台
TreeMapキーのソート順O(log n)範囲検索、最小/最大キー
EnumMapenum定義順効率的enumをキーにするMap
ConcurrentHashMap保証なし高並行性複数thread共有

HashMap

HashMap 基本操作
Map<String, Integer> ages = new HashMap<>();
ages.put("Alice", 20);
ages.put("Bob", 25);

int alice = ages.get("Alice");
int unknown = ages.getOrDefault("Carol", 0);
boolean hasBob = ages.containsKey("Bob");

ages.putIfAbsent("Carol", 30);
ages.computeIfAbsent("Dave", key -> key.length());
ages.merge("Alice", 1, Integer::sum); // 21

for (Map.Entry<String, Integer> e : ages.entrySet()) {
    System.out.println(e.getKey() + " = " + e.getValue());
}

TreeMap

TreeMap / NavigableMap
NavigableMap<Integer, String> ranking = new TreeMap<>();
ranking.put(100, "Gold");
ranking.put(50, "Silver");
ranking.put(10, "Bronze");

ranking.firstKey();      // 10
ranking.lastKey();       // 100
ranking.floorEntry(60);  // 50=Silver
ranking.ceilingEntry(60);// 100=Gold
ranking.subMap(10, true, 100, false);

LinkedHashMap

デフォルトは挿入順です。コンストラクタでaccess-orderを有効にすると「最近アクセスした順」を管理でき、LRUキャッシュ実装の基礎にも使えます。

Hashtable: 古い同期化Mapです。新規コードでは通常 HashMap、並行用途なら ConcurrentHashMap を検討します。

pq.addAll(List.of(30, 10, 20));

pq.poll(); // 10
pq.poll(); // 20
pq.poll(); // 30

20. ラムダ式 — 書き方から変数キャプチャまで

ラムダ式は、関数型interface（抽象メソッドが1つのinterface）の実装を簡潔に表す式です。単独で型を持つのではなく、代入先などの「ターゲット型」によって型が決まります。

構文

形例
引数なし() -> 42
引数1つx -> x * 2
複数引数(a, b) -> a + b
複数文x -> { var y = x * 2; return y; }
Lambda 基本
Predicate<String> isLong = s -> s.length() >= 5;
Function<String, Integer> length = s -> s.length();
Consumer<String> print = s -> System.out.println(s);
Supplier<UUID> uuid = () -> UUID.randomUUID();
BinaryOperator<Integer> add = (a, b) -> a + b;

メソッド参照

種類ラムダメソッド参照
staticx -> Integer.parseInt(x)Integer::parseInt
特定instancex -> out.println(x)out::println
任意instances -> s.length()String::length
constructor() -> new ArrayList<>()ArrayList::new

変数キャプチャ

effectively final
int threshold = 10;
Predicate<Integer> large = n -> n > threshold;
// threshold = 20; // これをするとラムダから参照できない

ローカル変数をラムダから参照する場合、その変数は final または effectively final（初期化後に再代入されない）である必要があります。

22. Stream API — filter / map / flatMap / collect / reduce

Streamはデータそのものを保持するCollectionではなく、データ処理のパイプラインです。中間操作は遅延評価され、終端操作が呼ばれると処理されます。

基本パイプライン
List<String> result = names.stream()
    .filter(name -> !name.isBlank())
    .map(String::trim)
    .map(String::toUpperCase)
    .distinct()
    .sorted()
    .toList();

主要な中間操作

操作意味
filter条件に合う要素だけ残す
map1要素を別の1要素へ変換
flatMap入れ子のStreamを平坦化
distinct重複除去
sortedソート
limit / skip件数制御
peek主にデバッグ用の観察

主要な終端操作

操作用途
toList / collect結果を集約
forEach各要素を処理
count件数
min / max最小/最大
findFirst / findAny要素検索
anyMatch / allMatch / noneMatch条件判定
reduce畳み込み

flatMap

List<List<T>> → List<T>
List<List<Integer>> nested = List.of(
    List.of(1, 2),
    List.of(3, 4)
);

List<Integer> flat = nested.stream()
    .flatMap(List::stream)
    .toList();

Collectors

groupingBy / partitioningBy / joining / toMap
Map<Integer, List<String>> byLength = names.stream()
    .collect(Collectors.groupingBy(String::length));

Map<Boolean, List<Integer>> evenOdd = nums.stream()
    .collect(Collectors.partitioningBy(n -> n % 2 == 0));

String csv = names.stream()
    .collect(Collectors.joining(", "));

Map<String, User> byName = users.stream()
    .collect(Collectors.toMap(
        User::name,
        Function.identity(),
        (oldValue, newValue) -> newValue
    ));

reduce

畳み込み
int sum = nums.stream()
    .reduce(0, Integer::sum);
parallelStream: 速くなるとは限りません。データ量、分割コスト、共有状態、順序制約を考えずに使うと逆に遅くなったり不具合の原因になります。

Stringを == で比較する
equals で内容を比較します。== は参照比較です。
HashSet / HashMap に入れる独自型で equals/hashCode が不整合
同値オブジェクトは同じhashCodeを返す必要があります。recordを使えるデータなら自動生成も有効です。
TreeSetに「違うオブジェクトなのに比較結果0」の要素を入れる
TreeSetはComparator/Comparableの比較結果0を同一要素として扱うため、片方が保持されません。
Map#get の null だけでキー不存在と判断する
Mapがnull値を許す場合、get(key) == null だけでは判別できません。必要なら containsKey を使います。
Streamの中で外部のListへaddする
副作用が増え、parallel化にも弱くなります。結果生成なら toList や collect を優先します。
Optional#get を無条件で呼ぶ
map、orElse、orElseGet、orElseThrow を用途に応じて使います。
ArrayListの途中挿入を大量に繰り返す
後続要素の移動が必要でO(n)です。データ構造やアルゴリズム自体を見直します。
可変キーをHashMapへ入れた後、hashCodeに使う値を変更する
検索不能になる可能性があります。Mapキーは実質的に不変な値オブジェクトが安全です。

interface / default

Q236. 出力は？

interface Left {
    default String value() { return "L"; }
}
interface Right {
    default String value() { return "R"; }
}
class Both implements Left, Right {
    public String value() {
        return Left.super.value() + Right.super.value();
    }
}

System.out.println(new Both().value());
A. L
B. R
C. LR
答え・解説
C。LR。複数interfaceのdefaultメソッドが競合する場合、実装クラスでオーバーライドして解決できます。InterfaceName.super.method()で各default実装を明示的に呼び出せます。
interface / static / compile error

Q237. 次のHammerはコンパイルできる？

interface Tool {
    static void info() { System.out.print("I"); }
}
class Hammer implements Tool {
    void test() {
        info();
    }
}
A. でき、Iと表示できる
B. できない
答え・解説
B。interfaceのstaticメソッドは実装クラスへ継承されません。Tool.info()のようにinterface名で呼び出す必要があります。
inheritance / private / trace

Q238. 出力は？

class Base {
    private String tag() { return "B"; }
    String show() { return tag(); }
}
class Child extends Base {
    String tag() { return "C"; }
}

Base x = new Child();
System.out.println(x.show());
A. B
B. C
C. コンパイルエラー
答え・解説
A。B。BaseのprivateメソッドはChildへ継承されず、Childのtag()はオーバーライドではありません。Base.show()内のtag()はBase自身のprivateメソッドを呼びます。
override / throws / modifiers

Q239. 次のオーバーライドはコンパイルできる？

import java.io.*;

class Parent {
    void load() throws IOException { }
}
class Child extends Parent {
    @Override
    void load() throws FileNotFoundException { }
}
A. できる
B. できない
答え・解説
A。オーバーライド側は、親メソッドが宣言したchecked例外と同じ型またはそのサブクラスを宣言できます。FileNotFoundExceptionはIOExceptionのサブクラスです。
constructor / initialization order

Q240. 出力は？

class Parent {
    Parent() { System.out.print("P"); }
}
class Child extends Parent {
    int x = mark("F");
    { mark("I"); }

    Child() { System.out.print("C"); }

    int mark(String s) {
        System.out.print(s);
        return 1;
    }
}

new Child();
A. PFIC
B. FIPC
C. PIFC
答え・解説
A。PFIC。まずスーパークラスの初期化とコンストラクタが実行され、その後にサブクラスのフィールド初期化子、インスタンス初期化ブロック、コンストラクタ本体の順で進みます。
super / static / constructor trace

Q241. 出力は？

class Parent {
    Parent(int n) { System.out.print(n); }
}
class Child extends Parent {
    static int make() {
        System.out.print("M");
        return 7;
    }

    Child() {
        super(make());
        System.out.print("C");
    }
}

new Child();
A. 7MC
B. M7C
C. MC7
答え・解説
B。M7C。super(make())では、親コンストラクタへ渡す引数を先に評価します。そのためmake()のM、Parent(int)の7、Child()本体のCの順です。
static / null reference

Q242. 次のコードはどうなる？

class Counter {
    static int value = 4;
}

Counter c = null;
System.out.println(c.value);
A. 4と表示
B. NullPointerException
C. コンパイルエラー
答え・解説
A。4。staticフィールドはインスタンスではなくクラスに属します。変数cがnullでも、この式ではインスタンスを参照せずCounter.valueとして解決されます。ただしクラス名で参照する書き方が推奨です。
constructor / inheritance / compile error

Q243. 次のコードはコンパイルできる？

class Parent {
    Parent(int n) { }
}
class Child extends Parent {
    Child() { super(1); }
}

Child c = new Child(2);
A. できる
B. できない
答え・解説
B。コンストラクタは継承されません。Childに宣言されているのは引数なしのChild()だけなので、new Child(2)に対応するコンストラクタは存在しません。
Map / computeIfAbsent

Q244. 出力は？

Map<String,Integer> map = new HashMap<>();
int[] calls = {0};

map.put("a", 10);
int x = map.computeIfAbsent("a", k -> {
    calls[0]++;
    return 20;
});
int y = map.computeIfAbsent("b", k -> {
    calls[0]++;
    return 30;
});

System.out.println(x + ":" + y + ":" + calls[0]);
A. 10:30:1
B. 20:30:2
C. 10:30:2
答え・解説
A。10:30:1。aにはすでに値10があるため計算処理は呼ばれません。bだけ関数が実行されて30が登録されるので、呼び出し回数は1です。
TreeMap / navigation

Q245. 出力は？

TreeMap<Integer,String> map = new TreeMap<>();
map.put(10, "A");
map.put(20, "B");
map.put(40, "C");

System.out.println(
    map.floorKey(25) + ":" + map.ceilingKey(25)

List / removeIf

Q246. 出力は？

List<Integer> xs =
    new ArrayList<>(Arrays.asList(1, 2, 3, 4));

boolean changed = xs.removeIf(n -> n % 2 == 0);
System.out.println(changed + ":" + xs);
A. true:[1, 3]
B. false:[1, 3]
C. true:[2, 4]
答え・解説
A。true:[1, 3]。removeIfは条件に一致する要素を削除し、1件以上削除した場合にtrueを返します。この例では偶数の2と4が削除されます。
Arrays.asList / backing array

Q247. 出力は？

String[] a = {"A", "B"};
List<String> list = Arrays.asList(a);

list.set(0, "X");
a[1] = "Y";

System.out.println(a[0] + ":" + list.get(1));

C. X:Y
答え・解説
C。X:Y。Arrays.asListで得られるListは元配列を背後に持つ固定長ビューです。List側のsetと配列側の代入は互いに反映されます。
array / clone

Q248. 出力は？

int[] a = {1, 2};
int[] b = a.clone();

b[0] = 9;
System.out.println(a[0] + ":" + (a == b));
A. 1:false
B. 9:true
C. 9:false
答え・解説
A。1:false。一次元のプリミティブ配列をcloneすると別の配列オブジェクトが作られ、要素値がコピーされます。bを書き換えてもaは変わらず、参照も異なります。
switch / fall-through / trace

Q249. totalはいくつ？

int total = 0;

for (int i = 1; i <= 3; i++) {
    switch (i) {
        case 1:
            total += 1;
        case 2:
            total += 2;
            break;
        default:
            total += 4;
    }
}

System.out.println(total);
A. 7
B. 9
C. 12
答え・解説
B。9。i=1ではbreakがないためcase 2までフォールスルーして3加算、i=2で2加算、i=3でdefaultの4加算となり合計9です。
enhanced for / reference trace

Q250. 出力は？

StringBuilder[] a = {
    new StringBuilder("A"),
    new StringBuilder("B")
};

for (StringBuilder s : a) {
    s.append("!");
    s = new StringBuilder("X");
}

System.out.println(a[0] + ":" + a[1]);
A. A:B
B. A!:B!
C. X:X
答え・解説
B。A!:B!。拡張forの変数sは配列要素の参照のコピーです。参照先のStringBuilderを変更すると配列からも見えますが、s自体を別オブジェクトへ再代入しても配列要素の参照は置き換わりません。
boolean / XOR

Q251. 出力は？

boolean a = true;
boolean b = false;
boolean c = true;

System.out.println(a ^ b ^ c);
A. true
B. false
C. コンパイルエラー
答え・解説
B。false。booleanの^は排他的ORです。true ^ false はtrue、その結果とtrueの排他的ORはfalseになります。
conditional operator / evaluation

Q252. 出力は？

int n = 0;
int x = true ? ++n : (n += 10);

System.out.println(n + ":" + x);
A. 1:1
B. 11:1
C. 10:10
答え・解説
A。1:1。条件演算子?:では選択された側だけが評価されます。条件がtrueなので++nだけが実行され、右側のn += 10は評価されません。

Q253. 出力は？

Object value = new int[] {3, 4};

Thread / interrupt flag

Q254. 2行の出力は？

Thread.currentThread().interrupt();

System.out.println(Thread.interrupted());
System.out.println(
    Thread.currentThread().isInterrupted()
);
A. true / true
B. true / false
C. false / false
答え・解説
B。true / false。interrupt()で割り込み状態が立ちます。staticメソッドThread.interrupted()は現在のスレッドの状態を返すと同時にその状態をクリアするため、続くisInterrupted()はfalseです。
Thread / synchronized / lock

Q255. 次のwork()について正しい説明は？

class Service {
    void work() {
        synchronized (new Object()) {
            // shared data を更新
        }
    }
}
A. Serviceの全インスタンスで同じロックを共有する
B. 同じServiceインスタンスへの複数呼び出しを確実に排他する
C. 呼び出しごとに別ロックが作られるため、共有データの排他には通常使えない
答え・解説
C。new Object()はwork()を呼ぶたびに新しいオブジェクトを作ります。別々の呼び出しは同じmonitorを共有しないため、共有データを守るロックとしては機能しません。
